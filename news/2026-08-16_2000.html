06「worktreesは死んだ。クラウドエージェントこそ未来」——47万行のレガシーJavaで複数エージェントの限界を検証

📰 本文 + 和越対訳

CursorのクラウドエージェントがGit worktreesに代わる開発環境として注目を集める中、あるエンジニアが47万行のStrutsベースJavaレガシーシステム「Mifos」を舞台に、複数エージェント並列実行と単騎エージェントの実力差を徹底検証した。実験は「実行」「並列化」「審判」の3軸で評価されたが、結果は期待を大きく裏切るものだった。アプリ起動自体に全エージェントが失敗し、「実行」の柱は崩壊。8スコープに分割した並列調査では100件超の指摘を行番号付きで抽出できたが、既知バグの検出率は12件中5件にとどまり、単騎のClaude Codeが発見した「双子のコピペバグ」をエージェント群は4試行で一度も特定できなかった。同一範囲を3体のレプリカで実行すると、検出には「安定・確率的・構造的盲点」の三層構造が存在することも判明した。消費トークンは約49.4Mに達したが課金はゼロで、律速となったのは同時実行上限（8〜10体）だった。エージェント群は「速さと網羅性」では優れるものの、設計レベルの裁定は今も人間かシングルエージェントが優位という結論に至った。

Trong khi cloud agent của Cursor đang thu hút sự chú ý như môi trường phát triển thay thế Git worktrees, một kỹ sư đã thực hiện kiểm chứng toàn diện trên hệ thống Java legacy 470.000 dòng dựa trên Struts có tên "Mifos", so sánh khả năng của nhiều agent chạy song song với agent đơn lẻ. Thực nghiệm đánh giá theo 3 trục: thực thi, song song hóa và phán xét — nhưng kết quả phủ nhận nhiều kỳ vọng. Tất cả agent đều thất bại trong việc khởi động ứng dụng, làm sụp đổ trụ cột "thực thi". Điều tra song song chia thành 8 phạm vi trích xuất được hơn 100 nhận xét có số dòng kèm theo, nhưng tỷ lệ phát hiện lỗi đã biết chỉ đạt 5/12, và "lỗi copy-paste đôi" mà Claude Code đơn lẻ tìm ra thì nhóm agent không phát hiện được qua 4 lần thử. Kết luận: agent nhóm vượt trội về tốc độ và độ bao phủ, nhưng phán quyết ở cấp thiết kế vẫn thuộc về con người hoặc agent đơn lẻ.

08認知的負債——AIが速く書いたコードの請求書は頭の中に届く

📰 本文 + 和越対訳

「技術的負債」ならぬ「認知的負債」という概念が、AI駆動開発の普及とともに開発者コミュニティで注目を集めている。技術的負債がコードベースに蓄積するのに対し、認知的負債は「AIが生成したコードを理解せずに受け入れた開発者の頭の中に蓄積する」という根本的な違いがある。著者は「20年かけて失われたものが、今や2週間で失われる」と表現し、AI生成コードで理由不明な条件分岐が急速に再生産されている現状を指摘する。技術的負債はリファクタリングで返済できるが、認知的負債は「コードを綺麗にしても人間の理解は変わらない」ため、別の対策が必要だ。利息は「レビューの差し戻し」「障害時の初動遅延」「引き継ぎ時の質問対応」として現れる。対策として、コードをAIに生成させる前に「自分ならこうする」という予想を3行程度書き留め、差分を記録していく週次の振り返りプロセスが提案されている。

Khái niệm "nợ nhận thức" (cognitive debt) — khác với "nợ kỹ thuật" thông thường — đang thu hút sự chú ý trong cộng đồng developer cùng với sự phổ biến của AI-driven development. Trong khi nợ kỹ thuật tích lũy trong codebase, nợ nhận thức "tích lũy trong đầu của developer đã chấp nhận code do AI tạo ra mà không hiểu nó". Tác giả diễn đạt: "thứ mất đi trong 20 năm, nay chỉ mất 2 tuần", chỉ ra thực trạng các điều kiện rẽ nhánh không rõ lý do đang được tái tạo nhanh chóng qua AI-generated code. Khác với nợ kỹ thuật có thể trả bằng refactoring, nợ nhận thức đòi hỏi biện pháp riêng vì "dù code có sạch đẹp, sự hiểu biết của con người vẫn không thay đổi". Giải pháp được đề xuất: trước khi để AI tạo code, hãy ghi lại 3 dòng dự đoán của bản thân, sau đó ghi nhận sự khác biệt và review hàng tuần để dần tích lũy hiểu biết thực sự.

11DuckDB v2.0 Async I/O: 3× Faster Parquet on S3, 20× Faster CSV — Remote Data Processing Gets Network-Saturating Speed

📰 Article (English)

DuckDB's upcoming v2.0 release introduces asynchronous I/O, a fundamental redesign of how the database handles remote data reads. The motivation: as DuckDB expanded into cloud storage and data lake scenarios (S3, GCS, Azure Blob), synchronous I/O left CPU threads idle waiting for network responses instead of processing data. The result was severe underutilization of available bandwidth. The new architecture introduces two thread pools: a REGULAR pool (one thread per CPU core) for computation, and an ASYNC pool (4× system threads, capped at 256) for blocking I/O. Rather than requesting data on-demand, the system employs read-ahead: multiple fetch operations are kept in-flight simultaneously across ASYNC threads, with a configurable read_ahead_depth controlling queue depth. Benchmarks are striking. Parquet queries on S3 drop from 8.23s to 2.84s — a 3× speedup. Uncompressed CSV on S3 improves from 878s to 45s — nearly 20×. Network utilization goes from ~5 Gbit/s (synchronous) to approaching the 25 Gbit/s hardware ceiling. Currently implemented for Parquet and uncompressed UTF-8 CSV; JSON and native DuckDB format support are planned. The feature is available now in DuckDB dev builds with async I/O as the default mode. The formal v2.0 release is scheduled for fall 2026.
