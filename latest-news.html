📰 本文 + 和越対訳

OpenAIは11月18日、新フラッグシップモデル「GPT-6.2 Astra」と「GPT-6.2 Sol」を公開した。AstraはマルチモーダルなリアルタイムAIアシスタントで、テキスト・画像・音声を横断した複合的な推論が可能となっている。一方のSolは研究・分析特化型として位置づけられており、長文の文書処理や複雑な論証を得意とする。 今回の発表で注目を集めているのが、安全性評価における「AI自己改善能力」の項目で初めて「High」評価を受けた点だ。OpenAIが独自に策定した危険性評価フレームワークによれば、このレーティングはモデルが自らの能力をある程度拡張できる可能性を示している。同社は外部4団体を社内に迎えた独立評価プログラムと連動させながら、段階的な安全対策を講じていると説明した。 両モデルは現時点でChatGPT PlusおよびProサブスクライバーに順次展開されており、API経由での法人向け利用も近日中に解放される予定だという。

OpenAI cho biết họ đang phối hợp với 4 tổ chức đánh giá độc lập được tích hợp bên trong công ty để triển khai các biện pháp an toàn theo từng giai đoạn.

B1「Mutation Testをやれ」——AI生成コードのテスト品質を計測する新しいアプローチ

📰 本文 + 和越対訳

Zennで注目を集めているmizchi氏の記事は、AIが生成するコードが増える現代において、テストそのものの品質を測る手段として「Mutation Testing（変異テスト）」の採用を強く訴えている。AIが書いたテストはカバレッジ数値こそ高く見えがちだが、実際にはバグを通過させてしまうケースが多いという問題意識が出発点だ。 Mutation Testingとは、コードの一部をわずかに変化させた「変異体」を大量に生成し、既存のテストがそれを検出（kill）できるかどうかで品質を評価する手法だ。変異体がkillされなければ、そのテストは実質的に意味がないとみなす。mizchi氏はmizchi/mutatorというOSSツールをZennで公開し、実際のAI生成テストに適用した結果、テストがコードの挙動変化を捉えられていないケースが多数見つかったと報告している。 「AIが書いたテストを信用するな。計測せよ」というメッセージは、AI駆動開発が普及する現場での新しい品質保証のあり方を提示しており、開発者コミュニティで大きな反響を呼んでいる。

Bài viết của mizchi trên Zenn kêu gọi áp dụng "Mutation Testing" (kiểm thử biến thể) như một phương pháp đo chất lượng test trong thời đại AI sinh code. Vấn đề được nêu ra là: test do AI viết thường có coverage cao về con số, nhưng lại để lọt nhiều bug thực tế. Mutation Testing tạo ra hàng loạt "biến thể" của code bằng cách thay đổi nhỏ, rồi kiểm tra xem test suite có phát hiện ra sự thay đổi đó không. Nếu biến thể không bị "kill", test đó thực chất vô nghĩa. mizchi đã phát triển công cụ OSS mizchi/mutator và áp dụng cho các test do AI tạo ra, phát hiện nhiều trường hợp test không thể nắm bắt được thay đổi hành vi của code. Thông điệp "Đừng tin test do AI viết — hãy đo lường nó" đang tạo ra tiếng vang lớn trong cộng đồng lập trình viên.

Security researchers at Wiz disclosed a critical unauthenticated remote code execution (RCE) vulnerability in Nginx, the web server powering an estimated 34% of all websites globally. The vulnerability resides in Nginx's HTTP/2 protocol implementation, allowing an attacker to send a specially crafted sequence of HTTP/2 frames that triggers a memory corruption condition — ultimately enabling arbitrary code execution without any prior authentication or user interaction. The flaw affects Nginx versions from 1.9.5 (when HTTP/2 support was introduced) through the latest stable releases. The attack surface is particularly broad: any publicly accessible Nginx instance with HTTP/2 enabled — which is the default on most modern configurations — is potentially vulnerable. Wiz researchers confirmed the vulnerability on both Linux and macOS deployments, and developed a proof-of-concept exploit during their research, though it has not been publicly released. Patches have been released in Nginx 1.27.4 (mainline) and 1.26.3 (stable). System administrators are urged to update immediately. As a temporary mitigation, disabling HTTP/2 (http2 off; in the server block) prevents exploitation, though it impacts performance. The CVE identifier has been assigned and CVSS scoring is under review — preliminary estimates place it in the Critical range (9.0+).
