C3Where .env Went Wrong — SecretSpec Argues the Ubiquitous File Became Architecture It Was Never Designed to Be

📰 Article (English)

SecretSpec, the company behind a secrets management specification tool, published a sharp analysis arguing that .env files — ubiquitous across virtually every software project — have expanded far beyond their original purpose as a simple value-delivery mechanism. The post traces how .env started as a convenience for setting three export commands, then accumulated additional responsibilities: serving as a project's configuration schema, secret store, onboarding documentation, CI interface, and deployment format all at once. The core problem: environment variables do one thing well (deliver strings to a process) but cannot encode whether a value is required, secret, safe to commit, production-only, or restricted to one service. The post also highlights that mixing secrets like STRIPE_API_KEY with ordinary settings like DEBUG in the same file makes the entire file sensitive.
