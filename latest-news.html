A1ドコモ「5G SA」今月3度目の障害——約6時間で復旧、原因は毎回同じ「交換機への通信集中」

📰 本文 + 和越対訳

NTTドコモは2026年11月16日、5G SAサービスに3度目の通信障害が発生したと発表した。午前10時2分に障害が始まり、午後3時58分に完全復旧するまで約6時間にわたって音声通話・データ通信・SMSが利用しにくい状態が続いた。同月5日と11日に続く今月3回目の障害であり、いずれの原因も「5G SA加入者を収容する交換機への通信集中」と一致している。 今回の障害はサイバー攻撃や不正アクセスとは無関係であることが確認されており、4G回線やMVNOユーザー、緊急通報への影響はなかった。ドコモは影響を受けた端末に対し、機内モードのオン・オフや再起動を案内した。5G SAは専用の5G設備のみで構成され、4G輻輳の影響を受けにくい反面、加入者が急増する中で交換機の負荷管理が課題として浮き彫りになっている。先月5日の障害は約14時間、11日は約9時間続いており、再発防止策の実効性が問われる状況だ。

NTT Docomo thông báo vào ngày 16/11/2026 rằng dịch vụ 5G SA đã xảy ra sự cố lần thứ ba trong tháng, kéo dài khoảng 6 tiếng từ 10:02 đến 15:58. Nguyên nhân giống hệt hai lần trước: lưu lượng truy cập tập trung quá mức vào thiết bị chuyển mạch phục vụ thuê bao 5G SA. Sự cố không liên quan đến tấn công mạng hay truy cập trái phép, và người dùng mạng 4G, MVNO không bị ảnh hưởng. Docomo hướng dẫn người dùng bật/tắt chế độ máy bay hoặc khởi động lại thiết bị để khắc phục tạm thời. Ba sự cố liên tiếp trong tháng khiến dư luận đặt câu hỏi về hiệu quả của các biện pháp phòng ngừa tái phát của nhà mạng lớn nhất Nhật Bản.

B1GoogleがKubernetes上でAIエージェントを10倍高密度実行する「Agent Substrate」と「gVisor」をCNCFに寄贈

📰 本文 + 和越対訳

Googleは「Agent Substrate」と「gVisor」をCloud Native Computing Foundation（CNCF）に寄贈すると発表した。AIエージェントはその実行時間の90〜95%をモデル推論・外部API・人間の承認待ちに費やしており、従来の1 Pod = 1エージェント構成ではリソースが無駄になる一方、サーバーレスではコールドスタートの遅延が避けられなかった。 Agent Substrateはアクター制御プレーンとデータプレーンをKubernetes上に構築し、エージェントのセッション・作業状態・メモリをアクターとして管理する。アイドル状態のアクターはスナップショットとして高速なティアドストレージに退避され、必要に応じて素早く復元される。これにより従来比10倍のエージェント実行密度を実現するとGoogleは主張する。gVisorはエージェントが実行するコードに対して安全なサンドボックス環境を提供する。CNCFへの寄贈によって、いかなるKubernetesクラスタにも移植可能な中立的基盤が整い、断片化を防ぐことが期待される。

Google thông báo trao tặng "Agent Substrate" và "gVisor" cho Cloud Native Computing Foundation (CNCF). Vì AI agent dành 90-95% thời gian chờ đợi (model inference, API ngoài, phê duyệt của con người), cấu hình truyền thống 1 Pod = 1 agent lãng phí tài nguyên, còn serverless gặp vấn đề cold start. Agent Substrate xây dựng control plane và data plane dạng actor trên Kubernetes: các actor idle được lưu snapshot vào tiered storage nhanh và khôi phục khi cần, giúp tăng mật độ thực thi agent lên 10 lần theo con số Google công bố. gVisor cung cấp môi trường sandbox an toàn cho code mà agent chạy. Việc trao tặng cho CNCF nhằm tạo nền tảng trung lập hoạt động trên mọi Kubernetes cluster tương thích, tránh phân mảnh hệ sinh thái.

📰 Article (English)

Security researcher Smitty van Bodegom disclosed a critical one-click Universal Cross-Site Scripting (UXSS) vulnerability in the MV2 Firefox version of uBlock Origin, with a related lesser issue in uBO Lite (MV3). The flaw was discovered by GPT-5.6 Sol and verified by the researcher; Claude wrote most of the proof-of-concept code. The vulnerability is now fixed (GHSA-cmqw-9r2w-6wv2). The attack chain exploits the extension's element picker, which runs as an extension page with a predictable path but randomized UUID per install. A default filter causes an XHR request to that UUID path, which an attacker's webpage can intercept to discover the UUID. With the UUID known, the malicious site embeds the picker in a hidden iframe and communicates over a MessageChannel. By injecting a newline into the picker's opt field, the attacker can inject a trusted scriptlet filter — the picker failed to validate the sender of messages. Trusted filters can inject JavaScript into any website the user visits, achieving universal script execution. The fix introduces a secret password generated by the content script to validate message origins. The researcher notes that an overlay or zero-opacity iframe could complete the final click step, making this a realistic one-click attack. Filters added this way persist as trusted until a full recompile. uBlock Origin users on Firefox MV2 should update immediately.
