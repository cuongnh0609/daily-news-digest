C3Valkey Replaces Skiplist with B+Tree, Cuts Sorted Set Overhead by Up to 43%

📰 Article (English)

Valkey, the Linux Foundation-backed open-source Redis fork, has merged a significant performance improvement: replacing the skiplist data structure used for sorted sets with a B+tree implementation, reducing per-element memory overhead by up to 43% and improving cache locality. Sorted sets (ZSET) are one of the most commonly used Valkey/Redis data structures for leaderboards, priority queues, time-series indexing, and rate limiting — making this change impactful for production deployments. The skiplist was Redis's original choice due to its simple concurrency properties and predictable O(log n) performance, but its pointer-heavy nature wastes memory and is unfriendly to CPU caches. The B+tree implementation is more compact, keeps data in contiguous memory pages, and shows better real-world throughput on range queries (ZRANGEBYSCORE, ZRANGE). The change is backward-compatible, requiring no changes to client code or data formats. Valkey's engineering team published detailed benchmarks showing 20–43% memory savings and 15–30% throughput improvements on common ZSET workloads. For teams running Redis/Valkey at scale with heavy sorted set usage, upgrading to the upcoming Valkey release that includes this change could yield significant infrastructure cost savings.
