B1「AIが管理画面を操作する時代」— WebMCPを使ったAI-first管理画面の設計とPoC実践

📰 本文 + 和越対訳

TOKIUMのエンジニアが、社内管理画面をLLMエージェントが直接操作できる「AI-first」設計へ移行する試みを公開した。背景には、社員がClaudeにブラウザ経由で管理操作を代行させるケースが増えたものの、セッション切れのたびに多要素認証が求められ非効率な状況があった。注目されているのが、W3Cコミュニティグループが策定中の新API「WebMCP」だ。document.modelContext.registerTool()という関数でページの機能をAIエージェントへツールとして公開できる仕組みで、現在ChromeのOrigin Trialが進行中だが、FirefoxやSafariはまだ未対応。チームはWebMCPの本採用を見送り、代わりにYAML形式でAPIツール一覧を記述したLLM向け「指示書ページ」を用意し、Claudeがそれを読んで既存APIを呼び出すアーキテクチャを暫定運用中だ。プロンプトインジェクションのリスクや未記載APIの呼び出し問題など課題はあるが、まず読み取り専用操作から段階的に展開する方針を取っている。

Kỹ sư của TOKIUM đã công bố một nỗ lực chuyển đổi màn hình quản trị nội bộ sang kiến trúc "AI-first", nơi các LLM agent có thể trực tiếp thao tác hệ thống. Nguyên nhân là do nhân viên ngày càng nhờ Claude thực hiện thay các thao tác quản trị qua trình duyệt, nhưng mỗi lần hết session lại phải qua xác thực đa yếu tố (MFA), gây mất hiệu quả. API mới đang được chú ý là "WebMCP" do W3C Community Group đang soạn thảo — cho phép đăng ký function của trang web thành tool cho AI agent qua hàm document.modelContext.registerTool(). Hiện Chrome đang chạy Origin Trial nhưng Firefox và Safari chưa hỗ trợ. Nhóm quyết định chưa áp dụng WebMCP, thay vào đó tạm thời sử dụng "trang hướng dẫn" mô tả danh sách API dạng YAML để Claude đọc và gọi API hiện có. Dù còn rủi ro prompt injection và khả năng gọi API không được liệt kê, nhóm đang triển khai từng bước, bắt đầu từ thao tác chỉ đọc (read-only).

C2Lock Your GitHub Actions — New Official Lockfile Support Ends SHA-Pinning Toil

📰 Article (English)

GitHub Actions now officially supports workflow lockfiles, dramatically simplifying supply-chain security for CI/CD pipelines. Previously, the best practice was manually pinning every action to a full commit SHA, which is tedious to maintain and hard to review. The new approach uses the gh-actions-lock CLI extension: running gh actions-lock rewrites SHA pins to version tags and generates .github/workflows/actions.lock, a machine-readable lockfile recording exact SHAs. Renovate and Dependabot both support the lockfile format, enabling automated updates with optional dependency cooldowns. GitHub recommends adding a CI verification job that runs gh actions-lock --verify to enforce lockfile integrity on every PR. The post also strongly recommends zizmor, a GitHub Actions security linter whose v1.32.0 is the first release with lockfile support. Without a lockfile, any tag in a workflow (like uses: actions/checkout@v4) can be silently repointed to malicious code in a supply-chain attack. The lockfile anchors tags to verified SHAs so such attacks are detected before they run.
