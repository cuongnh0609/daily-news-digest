The move underscores the increasingly competitive landscape in AI-assisted development tooling, where OpenAI's own Codex CLI and GitHub Copilot (through its Microsoft relationship) compete directly with Cursor. Cursor, which had gained significant traction as a Claude Code and Copilot alternative, now faces the challenge of rebuilding model partnerships. It reportedly still has integrations with Anthropic's Claude, Google's Gemini, and open-weight models via its native model router. Developers using Cursor on OpenAI models will need to switch providers or migrate workflows to another tool.

C-02I Accidentally Turned LLM Memory into Program Analysis — The Lemmalog Experiment

📰 Article (English)

A developer working on vulnerability research discovered that LLM memory systems perform far better when treated as program analysis rather than simple retrieval. The result is Lemmalog — a Datalog engine that maintains an evolving set of facts and logical relationships, used as the memory backend for an LLM agent. The core insight: LLMs forget previous conclusions during long investigations, suggest already-ruled-out approaches, or reason from invalidated assumptions. Standard RAG retrieval doesn't fix this because it treats memory as a bag of text rather than maintained logical state. Lemmalog splits the work: the LLM handles fuzzy extraction of natural language into structured Datalog facts, while Lemmalog handles deterministic reasoning — including retractions with support tracking, provenance queries, and temporal validity intervals. On the LongMemEval benchmark (102 questions), Lemmalog achieved 0.463 F1 with only ~2,700 tokens per question versus ~104,000 for full-context prompting — a 38× reduction in token usage. It performs especially well on adversarial questions (0.707 F1) and knowledge update scenarios (0.579 F1). The author frames this as "LLM agents as compilers": the LM is the probabilistic front-end; Lemmalog is the deterministic back-end.

Source: pwning.systems · 2026-08-29 · Author: matt_d · Read original →
🇻🇳 Bản dịch + 📖 Giải thích thuật ngữ
Một developer nghiên cứu lỗ hổng bảo mật đã phát hiện rằng hệ thống bộ nhớ LLM hoạt động tốt hơn nhiều khi được coi như phân tích chương trình thay vì chỉ là retrieval đơn giản. Kết quả là Lemmalog — một Datalog engine duy trì tập hợp facts và quan hệ logic, được dùng làm memory backend cho LLM agent. Insight cốt lõi: LLM thường quên các kết luận trước đó trong các điều tra dài, đề xuất lại những hướng đã bị loại, hoặc suy luận từ các giả định đã bị vô hiệu. RAG thông thường không giải quyết được vì coi bộ nhớ như một túi văn bản thay vì trạng thái logic được duy trì. Lemmalog phân chia công việc: LLM xử lý phần mờ — trích xuất ngôn ngữ tự nhiên thành Datalog facts có cấu trúc — còn Lemmalog xử lý phần tất định, bao gồm retraction kèm theo dõi phụ thuộc, provenance queries, và khoảng thời gian hợp lệ của facts. Trên benchmark LongMemEval, Lemmalog đạt F1 0.463 với chỉ khoảng 2.700 token mỗi câu hỏi, so với ~104.000 token khi dùng full-context prompting — giảm 38 lần lượng token. Hiệu suất đặc biệt tốt với các câu hỏi đối kháng (F1: 0.707) và cập nhật kiến thức (F1: 0.579). Tác giả định hình điều này là "LLM agent như compiler": LM là front-end xác suất, Lemmalog là back-end tất định.
Đây là pattern thiết kế quan trọng cho agent có bộ nhớ dài hạn — đặc biệt hữu ích khi xây dựng agent debugging, research agent, hoặc bất kỳ agent nào cần duy trì "world state" nhất quán qua nhiều turn mà không bị memory drift.

C-03GitHub Copilot in Visual Studio August Update: Org-Level Agents, Thinking Effort Controls, Git Code Review

📰 Article (English)

GitHub's August 2026 update to Copilot in Visual Studio introduces five meaningful changes for enterprise teams and individual developers. The most significant: organization-level custom agents can now be published and automatically appear in the agent picker across all repos in an org — enabling teams to deploy specialized, context-aware coding agents at scale without per-user configuration. Adjustable thinking effort is now available for supported models, offering Low / Medium / High controls that let developers trade off reasoning depth against token consumption depending on task complexity. This is especially useful for quick completions versus deep architectural analysis. A new "View all Copilot usage" panel gives users visibility into plan limits and consumption. The Git agent now performs code reviews on uncommitted changes or individual commits before they become pull requests, surfacing findings inline in the editor. This shifts code review earlier in the development loop — catching issues before they reach CI or a human reviewer. Enhanced model management lets users pin preferred models, hide unused ones, and view detailed capability cards including context windows and pricing per model. All features are available across all Copilot tiers including the free plan.
