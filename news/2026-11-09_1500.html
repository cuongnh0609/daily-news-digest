B-01Herdr.app と hc の上で Claude Code の「司令塔」エージェントを回す実践記

📰 本文 + 和越対訳

複数のAIエージェントを同時に走らせる場合、人間がそれぞれの状態を把握し続ける管理コストが急増する。この問題を解決するため、開発者の星野剛士氏はHerdr.appとhc（herdr-core）というツール上に「司令塔」エージェントのアーキテクチャを構築し、その実践をZennで公開した。構造はシンプルで、人間はひとりの司令塔エージェントとだけ会話し、実際の作業は司令塔が名前付きの子エージェントに委譲する。子エージェントはhc runやhc sendなどのコマンドを通じてhc（ターミナルとプロセスを所有する中核）を操作する。Herdr.appはその状態を表示するダッシュボードに過ぎず、再起動しても作業は継続される。初期実装では司令塔がhc wait --childrenをバックグラウンドで実行し続けていたため重複通知が多発したが、子エージェントがhc sendで報告するプッシュ型に変えたことで問題が解消された。司令塔の交代時にはハンドオフメモを残す仕組みもある。

Khi vận hành nhiều AI agent đồng thời, chi phí quản lý trạng thái của con người tăng vọt. Để giải quyết vấn đề này, nhà phát triển Hoshino Tsuyoshi đã xây dựng kiến trúc agent "tư lệnh" trên Herdr.app và hc, chia sẻ thực tiễn trên Zenn. Cấu trúc đơn giản: người dùng chỉ nói chuyện với một agent tư lệnh duy nhất, còn công việc thực tế được ủy quyền cho các child agent có tên. Các child agent điều khiển hc qua các lệnh như hc run, hc send. Herdr.app chỉ là dashboard hiển thị trạng thái. Phiên bản đầu dùng polling chờ báo cáo, nhưng đã chuyển sang mô hình push — child agent chủ động gửi báo cáo — giúp loại bỏ thông báo trùng lặp. Có cơ chế ghi handoff memo khi thay tư lệnh.

B-02自宅サーバーに Claude Code を常駐させ、スマホから24時間指示を出す — Remote Control + systemd 構成

📰 本文 + 和越対訳

C-01How I Fight AI Brain Fry — Managing Multiple Coding Agents Without Losing Your Mind

📰 Article (English)

Developer Sergey Kuhne describes a problem familiar to anyone running multiple AI coding agents in parallel: you start one task, context-switch to another while waiting, and soon you are juggling twenty threads with no clear sense of what needs attention. He calls this mental overload "AI brain fry" — the sequential tasks multiply faster than the human can close them out. His solution is to treat the workflow like a priority queue backed by version control. Every ticket is a markdown file committed alongside the code it concerns. An agent cycle handles research, build, test, and browser verification, while sensitive changes go on a branch with an explicit approval gate. The human never talks to individual agents; instead, all items requiring judgment are routed to a single "owner inbox" that is rebuilt from git each cycle. The most important rule is to work one item at a time: load its context, make a decision, then explicitly close the item and return it to the queue. Closing releases the context from working memory, preventing the lingering anxiety of unresolved threads. Two ongoing challenges remain: making context fast enough to load (a minute, not twenty), and preventing tickets from cycling endlessly while waiting for a ruling only the human can give. The post resonated widely on Hacker News, with many readers noting that the system is essentially applying software engineering discipline — git, queues, single-responsibility — to the human's own cognitive workflow.

C-02Weight-Space Programming: An AI Edits Another AI's Neural Weights Directly

📰 Article (English)

A researcher using Codex with Astra (GPT-6's agentic variant) set an unusual goal: modify the neural weights of Qwen3.5-0.8B so that it ends its Japanese answers with Zundamon-style endings (のだ/なのだ), without any fine-tuning or prompt engineering. The experiment, shared on Zenn, was inspired by a viral paper in which an LLM autonomously edited another model's weights. The method used activation contrast: the agent collected MLP and residual activations from 60 sentence pairs (plain vs. Zundamon-style) across three prompt contexts, then derived a "tone direction" vector. Only a single matrix — mlp.down_proj in layer 19 — was modified, using a rank-one-style update. The edit changed about 0.486% of the model's parameters. On a development set of 100 questions, 77 succeeded; on a held-out 50-question set, 36 succeeded. The researcher's key insight is that the significance is not what changed (direct weight editing is not new) but that an AI carried out the entire analysis and editing pipeline autonomously — a task a human could follow step-by-step but would never do at this speed. The experiment demonstrates that LLMs with agentic capabilities can perform weight-space programming as a tool-use loop, treating another model's internals as a codebase to be patched.
