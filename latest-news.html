📰 本文 + 和越対訳

C2GitHub Actions Workflow Lockfiles Enter Public Preview — Pin Action Dependencies to Reviewed Commits

📰 Article (English)

GitHub has launched workflow dependency lockfiles for GitHub Actions in public preview. The feature closes a critical supply-chain gap: when a workflow references an action by tag or branch rather than a full commit SHA, that reference can silently drift after a maintainer pushes a new commit. If the action is compromised between your last review and the next run, malicious code can execute in your CI/CD pipeline without any change to your own repository. Lockfiles tie every action dependency — including transitive dependencies and reusable workflows — to the exact commits reviewed during setup. Teams install the gh actions-lock extension, run the lock command for each workflow they want to protect, and commit the resulting .github/workflows/actions.lock file. From then on, GitHub Actions uses those pinned commits regardless of tag movement. Administrators can enforce adoption organization-wide or per-repository through a "Require lockfile" policy. Dependabot integrates with the lockfile: when it opens a version update for a locked action, it regenerates the lockfile entry in the same pull request, so reviewers see both the version bump and the new pinned SHA together. The preview is available across GitHub Free, Team, and Enterprise Cloud (including data residency). Lockfiles do not vouch for the safety of a dependency — teams should still audit actions before onboarding them.
