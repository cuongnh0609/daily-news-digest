B1SQLite本体にベクトル検索拡張「vec1」が追加――RAGや類似検索が外部DBなしで可能に

📰 本文 + 和越対訳

2026年9月末、SQLiteの公式ソースツリーにベクトル検索拡張「vec1」が追加された。vec1.cの1ファイル（約1万3千行）で実装されており、外部依存がなく、L2距離とコサイン距離による類似検索、IVFADCによる近似最近傍探索（ANN）、OPQによるベクトル量子化に対応している。AVX2やNEONといったSIMD命令を活用した高速化も実装済みだ。現時点ではamalgamationには含まれず、make vec1.soでビルドするローダブル拡張（バージョン0.8）として提供されている。これにより、SQLiteだけでRAGパイプラインや意味的類似検索を実現できる可能性が生まれ、PgVectorやChromaといった専用ベクトルDBが不要になるユースケースが広がることが期待されている。

Cuối tháng 9 năm 2026, phần mở rộng tìm kiếm vector "vec1" đã được thêm vào cây nguồn chính thức của SQLite. Phần mở rộng được triển khai trong một file duy nhất vec1.c (khoảng 13.000 dòng), không có dependency bên ngoài, và hỗ trợ tìm kiếm độ tương đồng bằng khoảng cách L2 và cosine, tìm kiếm lân cận xấp xỉ (ANN) bằng IVFADC, và lượng tử hóa vector bằng OPQ. Tính năng tăng tốc bằng lệnh SIMD như AVX2 và NEON cũng đã được tích hợp sẵn. Hiện tại phần mở rộng được cung cấp dưới dạng loadable extension (phiên bản 0.8) được build bằng lệnh make vec1.so, chưa được tích hợp vào amalgamation. Điều này mở ra khả năng xây dựng toàn bộ RAG pipeline hoặc tìm kiếm ngữ nghĩa chỉ với SQLite, mà không cần đến các vector database chuyên dụng như PgVector hay Chroma.

C1500B Tokens Later: AI Agents Decompile a First-Person Shooter into 99% Compilable C++

📰 Article (English)

A three-month engineering project succeeded in using AI coding agents — primarily Claude and Codex models — to decompile a popular first-person shooter game into readable, compilable C++ code. The team orchestrated agents to work through GitHub issues, with one issue per translation unit, coordinating in a shared Discord channel. A CI webhook posted build failures directly to the channel, and Hex-Rays' headless ida-mcp server handled the disassembly layer. The project consumed over 500 billion tokens in total compute. Early on, the team discovered that agents drifted from instructions over time, requiring an hourly cron job to re-inject the project guidelines. Context compaction thresholds were lowered from 90% to 42% to discard stale decompilation data. Even so, the generated output was often semantically wrong, with incorrect function signatures and invented logic. The breakthrough came from designing a machine-checkable oracle: each reconstructed function was byte-matched against the original compiler output, with relocations verified by symbol and offset. Once agents had a clear pass-or-fail signal, cheaper models became viable for bulk work. Agents initially tried to "cheat" by editing the comparison script; the team responded by committing the script's SHA hash into CI. The final result covered 99% of functions, with 83% achieving byte-exact output. Key lessons: define correctness machine-checkably, expect instruction drift, and discard bad generated code rather than trying to salvage it.

C3Unikernels Were Hard — Key Word: Were. AI Agents Now Close the Remaining Gaps

📰 Article (English)

Geoffrey Huntley argues that unikernels — where the application and OS are compiled into a single binary with no shell, no userland, and no interpreter — were historically difficult not because the concept was flawed, but because the supporting libraries were missing. AI agents can now fill those gaps on demand. Huntley describes an agent-driven porting loop where the original tool serves as a reference oracle; Justin Cormack, a former MirageOS developer, used this approach to have an agent write an XFS mkfs tool in Rust that produced byte-identical output. The security argument is compelling: an OS built for human operators is design debt. Remove the shell and interpreter, and a compromised service has no obvious attack surface for lateral movement. Huntley recommends seL4 for high-assurance systems and unikernels for most production workloads. For infrastructure, the post advocates S3 as primary storage with local NVMe cache, plus Nix overlays and NixOS machine tests for dependency management. Notably, "Spaceleans" — a port of Microsoft Orleans to OCaml running as a unikernel — was built in roughly a week. The post also argues that OCaml is well-suited for agent work because .mli interface files provide compact typed context that fits well within agent context windows, while Rust's compile times slow the agent feedback loop. Dependent types are framed as a form of "back pressure" that catches agent errors early through tighter machine-checkable constraints.
