09Agent Memory Needs Its OpenTelemetry Moment — Toward a Shared Memory Format for Coding Agents

📰 Article (English)

Today's coding agents — Claude Code, Codex, Cursor, and others — each store memory in incompatible formats. Some use instruction files like AGENTS.md or CLAUDE.md, others write to agent-managed note directories, hosted platforms, or knowledge graphs served through MCP servers. Each approach makes sense in isolation, but together they fragment the ecosystem: a note written by one agent cannot be read by another. Mads Thines of LoreKit draws a parallel with observability before 2019. Back then, every vendor shipped their own agent and data format. OpenTelemetry resolved this by agreeing on a data model, semantic conventions, a transport protocol, and reference implementations — while vendors kept competing on storage and analysis. The author proposes an analogous spec for agent memory: a record format with scope address, key, stable identity, lifecycle/expiry, authorship, and namespaced attributes. Interoperability would be provided through a versioned naming registry, a minimal MCP-exposed operation set (write, read, list, search, archive), and conformance tests. Existing proposals like Portable Memory, the Open Memory Protocol, and COGX mainly focus on exporting one person's memory between vendors. The harder, unsolved problem for coding tools is live shared addressing — multiple agents reading and writing the same scope concurrently. The post acknowledges prompt-injection risks through shared memory and closes with open design questions around governance, forgetting defaults, and linking records to source code.
