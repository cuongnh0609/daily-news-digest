B-01GoogleのSTAMP/STPA実践——SREにも使えるシステム安全分析の新アプローチ

📰 本文 + 和越対訳

Googleが社内SREの実践に取り入れているSTAMP/STPAというシステム安全分析手法が注目を集めている。この手法はMITのレヴェソン教授が2004年に提唱したもので、各コンポーネントが個別に正しく動作していても、システム全体として望ましくない結果をもたらしうるという「システム事故」の考え方に基づく。STPAはSLO/SLIでカバーしきれないプライバシー侵害や規制違反などの「絶対に許容できない損失」の分析に特に有効だ。実践では、①損失・ハザードの定義 ②制御構造のモデル化 ③安全でない制御アクションの特定 ④損失シナリオの分析、という4ステップで進める。LINEヤフーのSREが実際のバッチシステムを例にした実践報告では、プッシュ通知の重複送信や認証情報のログ漏洩といったリスクの洗い出しに有効だったという。

Phương pháp phân tích an toàn hệ thống STAMP/STPA mà Google áp dụng trong thực tiễn SRE nội bộ đang thu hút sự chú ý. Phương pháp này do Giáo sư Leveson của MIT đề xuất năm 2004, dựa trên quan điểm rằng ngay cả khi mỗi thành phần hoạt động đúng riêng lẻ, hệ thống tổng thể vẫn có thể dẫn đến kết quả không mong muốn. STPA đặc biệt hiệu quả trong việc phân tích những "tổn thất tuyệt đối không thể chấp nhận" như vi phạm quyền riêng tư hay vi phạm quy định pháp luật — những thứ mà SLO/SLI không thể bao phủ hoàn toàn. Trong báo cáo thực tế từ SRE của LINE Yahoo, phương pháp này đã giúp phát hiện các rủi ro như gửi thông báo push trùng lặp và rò rỉ thông tin xác thực trong log.

C-02External Sandboxes for Coding Agents — Prime Radiant Open-Sources Three Lightweight Isolation Runtimes

📰 Article (English)

Simon Willison documented a new pattern for safely running code generated by AI coding agents: the "external sandbox" approach, developed in collaboration with Prime Radiant. The core idea separates where the agent runs from where its generated code executes — the agent itself operates outside the sandbox while its code runs inside an isolated environment. Prime Radiant open-sourced three reference implementations in its GitHub organization: external-sandbox-v86 (runs Alpine Linux inside WebAssembly via the v86 emulator), external-sandbox-container (runs Alpine Linux in an Apple Containers instance), and external-sandbox-quicksand (uses Microsoft's Quicksand library with QEMU). All three expose the same localhost API, so Claude Code, Codex, or Pi can be pointed at any of them without code changes. Each sandbox optionally includes an HTTP/HTTPS allow-list proxy and a credential replacement mechanism, ensuring the agent never holds the actual secret. This pattern is particularly useful when experimenting with untrusted or local LLMs, where you want the model's code to run but cannot fully trust its output.
