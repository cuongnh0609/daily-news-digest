B1MCPの大型アップデート（2026-07-28）で何が変わったか——TypeScript SDK v2でステートレス設計を試す

📰 本文 + 和越対訳

2026年7月28日にリリースされたMCP（Model Context Protocol）仕様の大型アップデートは、プロトコルのアーキテクチャを根本から変える内容だった。最大の変更点は、従来の`initialize`/`initialized`ハンドシェイクと`Mcp-Session-Id`ヘッダーによるセッション管理が廃止されたことだ。これにより各リクエストは完全に独立したトランザクションとなり、プロトコルバージョンや機能情報は全てのリクエストの`_meta`フィールドに含まれる形になった。このステートレス設計への移行は、分散デプロイ環境での運用上の課題を解消するもので、スティッキーセッションや共有ステートストアが不要になり、サーバーレスやエッジ環境との親和性が大幅に高まった。さらに、支払い確認など中断が必要なフローには「MRTR（Multi Round-Trip Requests）」という仕組みが導入され、サーバーが`requestState`という不透明な文字列を返すことで、異なるインスタンスが処理を引き継げるようになった。TypeScript SDK v2では`@modelcontextprotocol/server`などパッケージが分割された。

Bản cập nhật lớn của MCP (Model Context Protocol) ra mắt ngày 28 tháng 7 năm 2026 đã thay đổi căn bản kiến trúc của giao thức. Thay đổi quan trọng nhất là việc loại bỏ cơ chế handshake `initialize`/`initialized` và quản lý session qua header `Mcp-Session-Id`. Từ đây, mỗi request là một giao dịch độc lập hoàn chỉnh, với thông tin phiên bản và capabilities được nhúng trong trường `_meta` của từng request. Thiết kế stateless này loại bỏ nhu cầu dùng sticky session hay shared state store, giúp MCP tương thích tốt hơn với môi trường serverless và edge computing. Đối với các luồng cần tạm dừng giữa chừng — như xác nhận thanh toán — giao thức giới thiệu cơ chế MRTR (Multi Round-Trip Requests): server trả về chuỗi `requestState` mờ đục, cho phép các instance khác nhau tiếp tục xử lý mà không cần duy trì bộ nhớ phiên. TypeScript SDK v2 cũng chia nhỏ thành các package riêng biệt như `@modelcontextprotocol/server`.
