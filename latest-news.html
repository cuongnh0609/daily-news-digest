📰 本文 + 和越対訳

Dù còn hạn chế như không đọc được cross-origin iframe hay bị chặn bởi native dialog, nhưng có thể giải quyết bằng cách lưu quy trình vào Skills. C1LangChain: Context Engineering — How Deep Agents Remember Without Losing Their Minds

📰 Article (English)

LangChain's engineering blog published a deep dive into "context engineering" — the set of techniques used in their open-source Deep Agents harness to keep long-running agents accurate as context windows grow. The central problem is "context rot": as agents accumulate tool outputs, instructions, and history over time, reasoning quality degrades. The team identifies five concrete countermeasures, all implemented as middleware hooks in the agent loop. First, offloading saves large tool results to the filesystem and gives the model only a short preview plus a file path. Second, summarization condenses older messages when usage nears the context limit while preserving recent messages verbatim and keeping the full history retrievable. Third, progressive skill loading shows only names and descriptions of instruction folders until a skill is actually needed. Fourth, subagent isolation runs noisy sub-tasks in a separate context window and returns only the final result. Fifth, a long-term memory markdown file is loaded at each run start and updated whenever the agent learns something worth preserving. Because memory is stored as plain files under developer-controlled storage, it is portable across models and providers. The article closes with six design principles: offload rather than truncate, keep compaction recoverable, load know-how on demand, isolate noisy work, own your memory, and make defaults customizable.

C2LangChain: The Most Common Questions About Agent Evals, Answered

📰 Article (English)

LangSmith's team published a comprehensive guide to agent evaluation, tackling the core challenge: unlike traditional unit tests, agent outputs vary between runs, multiple answers can be correct, and agents choose their own execution paths. The recommended approach is to pick one observable behavior, build a dataset of 10–20 examples from real production traces, and establish a baseline experiment. Every new failure becomes a dataset example, creating a continuous improvement loop. The article distinguishes offline evals (run against fixed datasets before shipping, catching regressions) from online evals (scoring live production traces without reference outputs, surfacing problems the dataset missed). Four evaluator types are covered: code evaluators for deterministic checks (fast and cheap), LLM judges for subjective criteria (require calibration with narrow binary questions), human review for highest-signal quality assessment, and pairwise evaluators for A/B comparisons. Importantly, the article clarifies that evals can operate at different granularities — single step, final response, full conversation, or environment end-state. The Harbor benchmark runner executes longer multi-step tasks in isolated containers and logs results to LangSmith experiments. The key takeaway: without evals, teams judge agent quality by anecdote, leading to regressions that only users discover in production.
