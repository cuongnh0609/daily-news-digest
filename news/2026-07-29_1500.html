B-01Claude Code RoutinesでPRを自動レビュー——サブスクリプション枠内でコードレビューを無料自動化

📰 本文 + 和越対訳

GitHubのプルリクエスト（PR）を自動レビューするために Claude Code Routines を活用する手法が、Zennで注目を集めている。既存のAIコードレビューサービス（CodeRabbit、Devin など）は1回あたり15〜25ドル程度のコストがかかるか、プライベートリポジトリでは有料プランが必須となるため、導入の敷居が高い。この記事では、すでにClaude Codeのサブスクリプションを契約しているチームが、追加コストゼロで自動PRレビューを実現する方法を解説している。具体的には、Routinesの設定画面で「Pull request: Opened」トリガーを設定し、レビュー用のスキルやコマンドをInstructionsフィールドに記述するだけで、PRオープン時に自動的にレビューが走るようになる。AIレビュー結果はGitHubのコメントとして記録されるため、チーム全体で確認・追跡できる点も利便性が高い。実装時のコンテキストに左右されないクリーンなレビューが可能な点も評価されている。

Một kỹ thuật tận dụng Claude Code Routines để tự động review pull request trên GitHub đang thu hút sự chú ý trên Zenn. Các dịch vụ review AI hiện có như CodeRabbit, Devin tốn khoảng 15–25 USD mỗi lần hoặc yêu cầu gói trả phí cho repo private, nên rào cản cao. Bài viết hướng dẫn cách đạt được auto PR review không tốn thêm chi phí cho các team đã có subscription Claude Code. Cụ thể: cấu hình trigger "Pull request: Opened" trong Routines và mô tả lệnh review trong trường Instructions. Kết quả review AI được ghi lại như comment trên GitHub, cả team có thể theo dõi. Ưu điểm khác là review được thực hiện với context sạch, không bị ảnh hưởng bởi context lúc implement.

📰 Article (English)

GitHub's npm registry announced a significant supply chain security upgrade on July 28, 2026: packages are now automatically scanned for malware before they become publicly available for installation, rather than at install time. This proactive approach introduces a short delay — typically 5 to 15 minutes, potentially longer at peak times — between publishing and availability. Developers and CI/CD pipelines that assume immediate availability after `npm publish` will need to accommodate this delay. The change also introduces a formal Dual-Use Content policy: packages that declare legitimate security-relevant capabilities (such as penetration testing tools, exploit frameworks, or credential testing utilities) must include a `contentPolicy` field in `package.json` and provide a `DISCLOSURE` file explaining the package's purpose and intended use. Additionally, dual-use packages require two-factor authentication enforcement during publishing — tokens that bypass 2FA are no longer permitted for direct releases. Once a package is declared dual-use, that designation cannot be removed in future versions; attempts to do so result in publication rejection. The Advisory Database now also ingests malware signatures from the OpenSSF malicious-packages repository, expanding detection coverage across npm, PyPI, and additional ecosystems. Taken together, these changes represent the most significant overhaul of npm's security posture in years.
