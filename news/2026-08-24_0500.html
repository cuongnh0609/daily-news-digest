B1コーディングエージェントが実装するUIの品質を上げる——デザインシステムとAgent Skillsの組み合わせ

📰 本文 + 和越対訳

AIコーディングエージェントが生成するUIの品質は、プロンプトの工夫だけでは限界がある——そう痛感したMOSHのエンジニアチームが、デザインシステムとAgent Skillsを組み合わせた独自の解決策を公開した。問題の核心は「仕様の散在」だ。Figma・Notion・Storybookにバラバラに存在する情報をエージェントが統合できず、複数回のフィードバックが必要になっていた。チームはJSDocアノテーションでStorybookコンポーネントにFigmaとNotionのURLを直接紐付け、エージェントが参照できるようにした。さらに3種類のAgent Skillを定義した。「design-context」で設計フェーズの情報を収集し、「design-review」で実装後の検証を行い、「design-principles」で判断基準を提供する。加えてGritQLを使ったカスタムlinterでトークンの誤用を検出し、Plopによるテンプレート自動生成でレビュー不要なコンポーネントを量産できる仕組みも整えた。結果として、ガイドライン準拠のUIがワンショットで生成されるようになり、反復サイクルが大幅に減少した。

Chất lượng UI do các AI coding agent tạo ra có giới hạn chỉ với việc tùy chỉnh prompt — đó là điều mà team kỹ sư của MOSH nhận ra, và họ đã công bố giải pháp độc đáo kết hợp design system với Agent Skills. Vấn đề cốt lõi là "thông tin phân tán": Figma, Notion và Storybook chứa thông tin riêng biệt mà agent không thể tổng hợp được, dẫn đến phải qua nhiều vòng feedback. C3JIT Compiling Code in 5 Microseconds — A Deep Dive into Sub-Millisecond Native Code Generation

📰 Article (English)

A detailed engineering post from malisper.me explores how to JIT-compile code in as little as 5 microseconds (5μs) — several orders of magnitude faster than typical JIT compilers like LLVM or even Cranelift. The author describes a technique based on template JIT compilation: instead of lowering from IR (intermediate representation) down through optimization passes, the compiler emits native machine code directly by filling in pre-allocated template stubs. Each template corresponds to a simple operation (integer add, branch, load) and contains fixed machine instruction bytes with slots for operand values. At compile time, the runtime just patches the operand slots — no IR, no instruction selection, no register allocation from scratch. The result is a JIT compiler that fits in under 500 lines of C, handles a subset of a Lisp-like language, and generates executable x86-64 code in the 5μs range on modern hardware. The technique trades generality for speed: no cross-function optimization, no loop vectorization. The author positions this as ideal for runtimes where compilation latency is itself a bottleneck — plugin sandboxes, hot-swappable DSLs, or AI agent tool execution environments where the overhead of a full compiler pipeline is unacceptable. The post reached 123 points on Hacker News.

IR (Intermediate Representation) /ˌɪntəˈmiːdiət ˌreprɪzenˈteɪʃən/ Biểu diễn trung gian giữa source code và machine code. Các compiler như LLVM dùng IR để tối ưu hóa trước khi phát ra code máy cuối cùng.
Template stub /ˈtɛmplɪt stʌb/ Khối machine code được phân bổ sẵn với các slot (lỗ trống) cho operand. Compiler chỉ cần điền slot thay vì tạo instruction từ đầu, giảm latency đáng kể.
Register allocation /ˈrɛdʒɪstər ˌæləˈkeɪʃən/ Bước trong compiler quyết định biến nào được giữ trong register CPU (nhanh) và biến nào phải spill ra bộ nhớ (chậm). Một trong các bước tốn kém nhất trong compilation.
DSL (Domain-Specific Language) /diː ɛs ɛl/ Ngôn ngữ lập trình được thiết kế cho một domain cụ thể (SQL cho database, CSS cho styling...) trái với general-purpose language như Python hay Go.
