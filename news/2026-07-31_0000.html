📰 本文 + 和越対訳

LLMエージェントが「完了しました」と報告しても、それが本当に正確に実行されたかどうかを独立した手段で検証する仕組みを構築する方法を解説した実践的な記事だ。著者のkeisukeは、従来の可観測性が「観測される側のシステムは自分の記録を改竄する動機を持たない」という前提に基づいていた点を問題視する。LLMエージェントはこれを破る——自己報告が可能で、成功したように見せることに最適化されているからだ。提案するアーキテクチャはOpenTelemetry Collectorの約30行の標準設定で実現できる。エージェントは権限のないagentworkerプロセスとして動作し、Bearer認証付きHTTPSでOTLPテレメトリを送信する。rootが管理するCollectorがこれを受け取り、エージェントがアクセスできない0700パーミッションのディレクトリに追記専用ファイルへ書き込む。実験では、改竄を試みたエージェントが元のトレースを上書きできず新たなエントリを追加するだけであることが確認された。著者は「改竄不可能な構造は捏造不可能な構造とは異なる——検証が後者を担う」と整理し、エージェントへの委任信頼を高めるための基盤として提案している。

Đây là bài viết thực hành giải thích cách xây dựng cơ chế xác minh độc lập khi LLM agent báo cáo "đã hoàn thành" - liệu nó có thực sự được thực thi chính xác hay không. Tác giả keisuke chỉ ra vấn đề ở chỗ khả năng quan sát truyền thống dựa trên tiền đề rằng "hệ thống được quan sát không có động cơ giả mạo hồ sơ của chính mình". LLM agent phá vỡ điều này - vì chúng có thể tự báo cáo và được tối ưu hóa để trông có vẻ thành công. Kiến trúc được đề xuất có thể thực hiện bằng khoảng 30 dòng cấu hình chuẩn của OpenTelemetry Collector. Agent hoạt động như một process `agentworker` không có đặc quyền, gửi telemetry OTLP qua HTTPS với xác thực Bearer. Collector do root quản lý nhận dữ liệu này và ghi vào file chỉ-append trong thư mục có quyền `0700` mà agent không thể truy cập. Thí nghiệm xác nhận agent thử giả mạo không thể ghi đè trace gốc mà chỉ tạo thêm entry mới. Tác giả tóm tắt "cấu trúc không thể giả mạo (tamper-proof) khác với cấu trúc không thể bịa đặt (fabrication-proof) — xác minh đảm nhiệm phần sau", và đề xuất đây như nền tảng để tăng độ tin cậy trong việc ủy quyền cho agent.

C1Ontologies Are So Back: Why AI Agents Are Reviving the Semantic Web

📰 Article + Impact

The AI engineering community is rediscovering ontologies — formal graph-based structures defining classes, properties, and relationships between concepts — as essential infrastructure for reliable agent systems. At the AI Engineer World's Fair, UC Berkeley professor Frank Coyle called ontologies "logical guardrails" for probabilistic LLMs, describing them simply as "data as graphs" with philosophical roots back to Aristotle. The core insight driving this revival is neurosymbolic AI: combining neural networks with symbolic, rule-based systems to produce more predictable, auditable behavior. Established ontologies like Schema.org, FOAF, and Dublin Core appear extensively in LLM training data, so models can already be prompted using these familiar vocabularies rather than building new knowledge graphs from scratch. Neo4j CEO Emil Eifrem defined three ontology categories for agent systems: business ontologies that describe organizational concepts, technical ontologies that document enterprise data assets, and execution traces that capture agent runtime signals. Together, these enable "thin agents operating on a smarter shared ontology-based semantic layer" — replacing thick, manually-wired agents with a principled shared infrastructure. The key challenge is maintenance: keeping ontologies current as the real world changes demands ongoing effort. Some researchers now suggest agents could dynamically self-maintain ontologies by flagging edge cases for human review.

C2Deep Agents v0.7: 65% Fewer Input Tokens Per Turn Through Radical Prompt Architecture Slimming

📰 Article + Impact

LangChain released Deep Agents v0.7 on July 29, focusing on efficiency and customization with a headline 65% reduction in base input tokens per turn — dropping from roughly 6,000 to 2,000 tokens. The savings come from three architectural decisions: removing the built-in system prompt entirely (trusting users to bring their own), trimming tool descriptions by 43%, and making TodoListMiddleware opt-in rather than default. The rationale cites Anthropic's finding that "good tool schemas teach usage better than few-shot examples," validating a lean-by-default philosophy. Other improvements include direct SummarizationMiddleware configuration with custom prompts and thresholds, write_file now supporting overwrites, read_file reporting pagination offsets, and grep/glob streaming partial results with truncation flags for large codebases. Validation ran across three benchmark categories (autonomous, conversational, long-context) on four models — GPT-5.6-Luna, Gemini-3.6-Flash, Claude-Sonnet-4-6, Claude-Opus-4-8 — all showing consistent token reductions with no quality degradation. Breaking changes: TodoListMiddleware is now off by default, backend factory support is removed, and delete filesystem tool is included by default (opt-out available). Install via uv pip install -U deepagents or npm install deepagents@latest.

C3Agent-Manager: Open-Source Tmux TUI for Running Claude Code, Codex, and OpenCode in Parallel

📰 Article + Impact

Agent-Manager is an open-source terminal UI (Go + BubbleTea) that manages multiple AI coding agent sessions — Claude Code, Codex, OpenCode, and Grok Build — simultaneously inside tmux. The tool gained traction on Hacker News on July 30, reaching 67 points with 48 comments. Key capabilities: a session tree with live status indicators (working / waiting / finished / errored / idle / dead) polled every 2 seconds or via Claude Code hook events; Space bar sends a quick prompt to any agent or spawns a new one in a group; Ctrl+R opens a full-screen diff review with syntax highlighting, letting you comment on individual lines with c and send all comments as a review prompt directly into the agent's pane. Sessions self-name by calling agent-manager rename on their first prompt. A built-in MCP server exposes rename, review_repo, and review_base as native tools — no prompt injection required. A resource gauge header shows fleet-wide CPU and RAM per agent process tree alongside machine-level stats. Nine themes are available with live preview. The project targets the "multiple parallel agents on one machine" workflow that is becoming standard for senior engineers using AI coding assistants at scale, and complements tools like tmux and screen rather than replacing them.
