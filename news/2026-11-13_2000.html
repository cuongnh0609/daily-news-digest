C222-Year-Old PostgreSQL Type-Confusion Bug Turned Into RCE — CVE-2026-6460 Drops with 52 Security Commits

📰 Article (English)

Security researcher Mehmet Ince published part three of his detailed write-up on turning a type-confusion primitive in PostgreSQL core into remote code execution, now assigned CVE-2026-6460. The root bug dates back approximately 22 years and was originally discovered while researching a ClickHouse extension for PostgreSQL. The attack chain works by creating a composite column typed as uuid, building a prepared statement against it, then using ALTER TYPE to change the column to bytea. Because stored bytes are not converted, the uuid output function reads bytea-layout memory as a UUID header, causing a crash that can be steered into an exploitable state. From there, the researcher demonstrates building a memory leak via a confused array element type and hijacking an expanded-object method table to reach system(). The PostgreSQL security team landed fixes on November 9, 2026, in a release that includes 52 new CVEs — with six related to this research. The researcher reports having shared proof-of-concept code with multiple managed PostgreSQL providers in advance. All PostgreSQL users should upgrade immediately. The researcher will present a 90-minute deep-dive at the Prague PostgreSQL Meetup on November 30, 2026.
