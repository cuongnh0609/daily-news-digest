B-01Claude Mods 入門——Function Hooksで Claude Code を深くカスタマイズする新プラグインシステム

📰 本文 + 和越対訳

Zennに公開されたこの技術記事では、Claude Code向けのプラグインシステム「Claude Mods」の仕組みと実践的な使い方を解説している。従来のフックが外部プロセス経由の通信に依存していたのに対し、Claude Modsの「Function Hooks」はTypeScript関数をClaude Codeのエンジンに直接ロードする方式を採用しており、より深いカスタマイズが可能だ。イベントシステムはtool.callやui.render、session.startを含む40以上のイベントに対応し、Claude Codeの動作を観察するだけでなく変更することもできる。セキュリティモデルとして5層のチェーン構造（prepend → user → append → builtin → core）を持ち、組織ポリシーを外側レイヤーに配置することで個人モッドによる改ざんを防いでいる。公式モッドとしてdiff（UIパネル表示）やagents-md（指示ファイル処理）などが提供されており、コミュニティによるcc-arcade（組み込みゲーム）といった実装例も登場している。

Bài viết kỹ thuật trên Zenn giới thiệu hệ thống plugin "Claude Mods" cho Claude Code, đặc biệt là cơ chế "Function Hooks" cho phép load trực tiếp hàm TypeScript vào engine của Claude Code thay vì giao tiếp qua tiến trình ngoài. Hệ thống sự kiện hỗ trợ hơn 40 loại event như tool.call, ui.render và session.start, không chỉ quan sát mà còn có thể can thiệp vào hành vi của Claude Code. Mô hình bảo mật gồm 5 lớp chuỗi (prepend → user → append → builtin → core) giúp chính sách tổ chức được đặt ở lớp ngoài để ngăn các mod cá nhân can thiệp không được phép. Các mod chính thức như diff và agents-md đã có sẵn, cộng đồng cũng bắt đầu đóng góp các mod thú vị như cc-arcade. Đây là bước tiến đáng chú ý trong việc mở rộng khả năng tùy biến môi trường phát triển AI-driven.

C-02"Why MCP Was Always a Bad Idea" — A Contrarian Take on the Limits of Tool Protocols

📰 Article (English)

Engineer Maharshi Patel published a provocative post arguing that the Model Context Protocol has been rendered obsolete by the very capability improvements in LLMs it was designed to support. The core argument: modern AI agents can already write scripts, compose multiple services, and call APIs they have never seen before — making a specialized intermediary protocol unnecessary overhead. Patel identifies four concrete failure modes. First, context bloat: registering multiple MCP servers with many tools floods the model's context window, requiring awkward workarounds like generic search-and-execute patterns. Second, MCP's machine-readable output formats (JSON/XML) consume far more tokens than human-readable alternatives. Third, modern models can explore CLIs independently using --help flags without needing pre-registered tool schemas. Fourth, the protocol adds latency and infrastructure complexity that direct HTTP calls do not. His proposed alternative: standardize agent-friendly HTTP APIs using Accept: text/markdown headers for compact responses and Accept-Language for locale-specific docs, then retire MCP infrastructure in favor of terminal access and documented REST APIs. The post generated significant Hacker News discussion (182 points), with rebuttals focusing on security boundaries and enterprise governance as MCP's genuine value-add that raw terminal access cannot provide.
