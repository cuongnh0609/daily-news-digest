B1仕様書から「保証台帳」へ——GDD（保証駆動開発）で Claude Code 時代の品質管理を再設計する

📰 本文 + 和越対訳

Claude Codeに実装を委ねることで開発スピードが飛躍的に上がった一方、手戻りや意図しない退行が増えたという開発者の声が増えている。Zennに投稿されたGDD（Guarantee-Driven Development：保証駆動開発）の提案は、この問題に正面から向き合ったアプローチだ。従来のテスト駆動開発が「正しく動くか」を確認するのに対し、GDDは「何を壊してはいけないか」を明示的に台帳化し、AIエージェントがコードを書くたびにその保証リストと突き合わせる設計を推奨する。Claude Codeが生成したテストは実行すれば緑になるが、保証台帳に沿った変更の整合性は別途人間が検証する必要があるという洞察が核心にある。仕様書という静的文書ではなく、変更のたびに更新される「生きた台帳」が、AI駆動開発時代の品質担保の軸になるという提言だ。

Khi Claude Code được dùng để delegate toàn bộ việc implementation, tốc độ phát triển tăng vọt nhưng kéo theo nhiều lần làm lại và regression không mong muốn. Bài viết trên Zenn đề xuất GDD (Guarantee-Driven Development — Phát triển hướng đảm bảo), một cách tiếp cận trực diện với vấn đề này. Thay vì TDD kiểm tra "có chạy đúng không", GDD yêu cầu ghi rõ ràng "không được phá vỡ điều gì" thành một "sổ cái bảo đảm" (保証台帳), và mỗi khi AI agent viết code thì phải đối chiếu với danh sách đó. Insight cốt lõi là: test do Claude Code sinh ra chạy xanh, nhưng tính nhất quán với sổ cái bảo đảm cần con người kiểm tra riêng. Tác giả lập luận rằng thay vì "tài liệu spec" tĩnh, cần một "sổ cái sống" được cập nhật mỗi khi có thay đổi — đó mới là trục bảo đảm chất lượng trong kỷ nguyên AI-driven development.

📰 Article (English)

A position paper circulating on Hacker News with 260 points argues that large language models have a fundamental, architecture-level limitation in tasks requiring true state tracking across reasoning steps — what the authors call "jumping" between non-adjacent states. The paper provides systematic evidence across four task families: grid navigation, multi-step arithmetic with intermediate carries, stateful simulation (e.g., tracking inventory across many transactions), and recursive data structure manipulation. The core claim is that transformer attention without explicit external state is insufficient for these tasks — models achieve high accuracy on short chains but collapse near-exponentially as chain length grows. Critically, the paper argues this is not a training data or scale problem: larger models show the same degradation curve, just shifted right. The proposed solution involves hybrid architectures pairing LLMs with explicit state machines or scratchpad memory managed externally. For agentic systems, this means the popular ReAct pattern (reason-act in single context) may be fundamentally brittle for tasks that require true stateful tracking over long horizons. The paper has sparked significant debate about whether this is a call for new architectures or merely more rigorous prompting and tool use.
