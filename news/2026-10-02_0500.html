📰 本文 + 和越対訳

AIがコードを生成する時代において、「何を実装するか」の意思決定がエンジニアの中心的な役割となっている。本記事では、AI駆動開発における設計ドキュメントの書き方と、その仕様をテストで自動検証するアプローチを提案する。著者は、従来の開発ではコード記述のプロセスに設計判断が埋め込まれていたが、AIに実装を委譲する場合はコードの外に設計を明文化しなければならないと主張する。具体的な手法として、Pythonのsys.monitoring APIを使って実行時の関数呼び出しを記録し、Mermaidシーケンス図で記述した仕様との一致をプログラムで検証する実装例を示す。人間のレビューは「このコードでよいか」から「この仕様でよいか」へ重心が移るべきであり、Spec-Drivenなアプローチが生産性と品質の両立につながると結論付けている。

C-03RIP, Vector Database: turbopuffer v3 Decouples ANN from the Primary Index — A Fundamental Storage Rethink

📰 Article (English)

turbopuffer has announced v3, a fundamental architectural redesign that repositions approximate nearest neighbor (ANN) search from the primary index to just another secondary index. The provocative title "RIP, vector database" signals a philosophical shift: vector search is an important capability, but building an entire storage system around it creates serious structural problems. The v1/v2 architecture stored everything keyed by ANN cluster addresses, which caused three cascading issues: storage amplification when documents had multiple vector embeddings (forcing full document duplication), write amplification during ANN rebalancing (where vector changes cascaded through all related indexes), and limited vectorization because query engines needed different block sizes but all were constrained to ANN cluster size of 100–200 documents. v3 separates the primary index from ANN logic entirely. Documents are stored with a standard primary key, and ANN becomes a secondary index like any other. This unlocks much larger block sizes for query engines, eliminates duplication, and enables "many more SQL queries" to run efficiently alongside vector search. The team reports a 100% CI pass rate on v3 and is now running performance optimization before production rollout, with public benchmarks forthcoming.
