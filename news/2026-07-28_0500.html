B1AndroidでセカンドブレインをOSSで構築——Obsidian・Termux・Claude Codeで知識管理を一元化

📰 本文 + 和越対訳

Zennに投稿された記事が注目を集めている。著者はAndroidスマートフォンのみを使い、Obsidian・Termux（proot Ubuntu）・Claude Code・ChatGPT・Gitという完全オープンなツールスタックで「セカンドブレイン」を構築した経験を共有している。システムの核心はObsidianのvaultをGitHubで同期させ、Termux上のClaude CodeがAIエージェントとして知識の整理・タグ付けを担う構成だ。フォルダ構成は inbox/（一時保存）、knowledge/（長期参照）、system/（AIルール共有）、projects/（プロジェクト管理）の4層に分かれており、全自動ではなく /organize-notes コマンドを手動でトリガーする設計が特徴的だ。AI処理とGit管理の分離により、ナレッジベースとコードベースを明確に区別できる点が実用的と評価されている。

C3Misago Drops React, Adopts HTMX: 85KB JS Reduction and Cleaner Architecture for a Django Forum

📰 Article (English)

The Misago open-source Django forum project has documented its multi-year migration from React.js to HTMX, achieving significant gains in simplicity and bundle size reduction. The core problem was a dual-rendering architecture requiring every public view to be implemented twice: once as a Django template and once as a React component, plus JSON API serializers in between. This created cascading friction — plugin developers had to master both Django and React to customize anything, translation strings were duplicated across two separate .po files, and large JavaScript bundles degraded mobile performance. Rather than migrating to another JavaScript framework (Next.js, Nuxt, SvelteKit), the team adopted HTMX, which uses server-rendered HTML "islands" updated dynamically via declarative HTTP attributes — essentially the jQuery ajax pattern made declarative, without a full framework. The results are concrete: replacing the account settings page cut 37KB of uncompressed JS (17KB gzipped); the threads list replacement cut an additional 48KB (8KB gzipped). Combined, the migration reduced the JS payload by approximately 85KB uncompressed and 25KB gzipped. The project continues incrementally, with the approach validated in production since mid-2024.
