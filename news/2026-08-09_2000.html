06AIエージェントの「ループ」を10種類に分類——検出しきい値の設計が根本から変わる

📰 本文 + 和越対訳

AIエージェントが無限ループに陥るパターンを体系的に分類し、それぞれに最適な検出しきい値を設計するという実践的な考察がZennに投稿され、注目を集めている。著者は10種類のループ現象を「同一操作の完全反復」「2状態間の振動」「進捗のない継続」「逆方向の失敗」という4つの系統に整理した。核心的な洞察は、エージェントが自分自身の進捗を客観的に測る手段を持っていない点が、あらゆるループの共通根本原因だという指摘にある。また「完全一致の連続反復」と「頻度ベースの反復」では適切なしきい値が桁違いに異なるため、別々の検出器が必要と論じている。さらに、同じコマンドの繰り返しであっても、ポーリング（正当な待機）と異常なループは「処理結果の変化の有無」で区別できるという実装上の知見も提示されており、エージェント品質管理に関心を持つ開発者の間で高く評価されている。

10Turn One Giant AI-Generated Pull Request Into a Reviewable Stack

📰 Article (English)

GitHub's engineering blog describes how to use stacked pull requests to make AI-generated code reviewable without sacrificing maintainability. The core problem: coding agents like Claude Code, Copilot Workspace, or Codex produce large diffs (often 1,000+ lines) that reviewers cannot meaningfully assess in a single pass. The stacked PR technique decomposes a large feature into logically ordered, dependent slices — typically: data model, API layer, business logic wiring, then UI — where each slice is an independently reviewable PR that builds on the one below. The `gh stack` CLI handles the mechanics: it manages branch chains, automatically rebases downstream PRs when an upstream one changes, and resolves ordering conflicts. The article frames this as the fundamental tradeoff of AI-generated code: "one giant PR is hard to review, while dozens of tiny ones are hard to maintain." Stacked PRs thread the needle by keeping diffs small enough for humans to evaluate while preserving the coherent narrative of a complete feature. This workflow is now directly supported by GitHub Copilot Workspace when creating agent-generated PRs.
