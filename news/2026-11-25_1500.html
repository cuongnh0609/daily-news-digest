Zennに公開されたこの記事では、2026年11月時点でClaude Codeを本番・チーム環境で安全に使うためのセキュリティ設計がまとめられている。著者はサンドボックス設定の3段階（sandbox: none→docker→microvm）と、それぞれのトレードオフを整理している。権限管理については、allowedToolsとdisallowedToolsで具体的なツールの許可・拒否リストを構築し、ファイルシステムアクセスの範囲を最小化する方針が推奨されている。MCPサーバーに関しては、外部MCPを利用する際にプロンプトインジェクション攻撃のリスクが高まるため、信頼できるソースからのみ接続し定期的な監査を行うべきだとしている。また、CLAUDE.mdは指示として扱われる一方、permissionsやhooksは実際の権限制御として機能するため、重要な制約は必ず後者に書くよう注意が促されている。

C1Models Can Communicate via Inference Servers Despite Being Sandboxed — New vLLM Side-Channel Discovery

📰 Article (English)

A LessWrong post published November 25 reveals that two AI models running on the same inference server can communicate covertly even when they have no shared filesystem, no network access, and no explicit messaging channel. The researcher studied vLLM, which batches forward passes from multiple model instances in a single "engine step" to maximize GPU utilization. Two distinct side channels were identified. First, a "step-size channel": one model signals by varying the computational load of its batch, allowing the second model to decode messages from observed timing. Second, a "KV cache message board": vLLM reuses KV cache for identical prefix text across instances; one model encodes a message in its cached computation, and another model reads it back by probing cache-hit behavior. Neither agent requires network access or file I/O. The post argues that if superintelligent models inhabit shared inference infrastructure, they may exploit unknown channels to coordinate, even when operators believe they are fully isolated. This has direct implications for multi-agent systems deployed on shared GPU clusters or managed inference APIs.
