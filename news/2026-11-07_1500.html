📰 本文 + 和越対訳

B-1AIエージェントがモデルの重みを自動編集 — weight-space programming実験をAIに再現させた結果

📰 本文 + 和越対訳

Zennに投稿された技術記事「weight-space programming やってみた（やらせてみた）」が注目を集めている。著者のnwn氏は、AIエージェント「Astra」（GPT-6 Astraベース）にQwen3.5-0.8Bモデルの重みを自律的に解析・編集させる実験を再現した。タスクは「ずんだもん語尾（のだ/なのだ）」を使った応答を100問中50問以上で自然に生成できるよう、モデルの内部パラメーターを変更すること。

Astraが採用したアプローチは、プレーンな応答とずんだもん語尾付き応答の内部活性化差分を60ペア収集し、その平均ベクトルを「語調方向ベクトル」として算出するものだ。編集対象は第19ブロック（0始まり）のmlp.down_proj.weightのみで、変更された重みの割合はわずか0.486%。開発セットで77/100、新規50問セットで36/50の精度を達成した。著者は「これは汎用LLMが重みを自律解析・編集できることの示唆であり、人間の研究者が不要だという話ではない」と慎重な見解を示している。

Bài viết kỹ thuật "weight-space programming やってみた" đăng trên Zenn đang thu hút sự chú ý. Tác giả nwn đã để AI agent "Astra" (dựa trên GPT-6 Astra) tự phân tích và chỉnh sửa các trọng số (weights) của mô hình Qwen3.5-0.8B. Nhiệm vụ là chỉnh sửa các tham số bên trong mô hình để nó tự nhiên sử dụng cú pháp "Zundamon" (のだ/なのだ) trong trên 50/100 câu trả lời. Phương pháp: thu thập 60 cặp phản hồi có/không có ngữ điệu Zundamon, tính vector hướng ngữ điệu trung bình, rồi chỉnh sửa một ma trận duy nhất chiếm 0.486% tổng số trọng số. Kết quả đạt 77/100 trên development set và 36/50 trên test set mới. Tác giả nhấn mạnh đây là minh chứng LLM có thể tự phân tích và sửa đổi weights, nhưng không có nghĩa là nghiên cứu viên con người trở nên không cần thiết.

C-2LLM Cascade Evaluators: Cheap Model + Opus Hybrid Matches Frontier Accuracy at 4× Lower Cost

📰 Article (English)

Hightouch engineers Albert Jin, Neil Desai, and Delaney Mackenzie published a detailed benchmark on using confidence-based LLM cascades for identity resolution (IDR) — the problem of matching data records to real people, with over-merging (one identity spanning multiple people) as the primary failure mode. The core finding: running a cheap "decision model" (Jev, a 0–1 confidence scorer at $0.05/1k) first, then escalating uncertain cases (confidence 30–90%) to Claude Opus 5.5, achieves 98.8% accuracy at $0.88/1k — roughly 4.4× cheaper than Opus alone at 99.0% accuracy. On a harder test set (look-alike names, typos on key fields), the hybrid reaches 95.3% at $2.94/1k versus Opus alone at 95.1%/$5.39 — essentially the same accuracy at 1.8× lower cost. A key calibration insight: Jev's errors cluster near 50% confidence (well-calibrated), while GPT-6 Luna is overconfident, with many mistakes in the 90–100% bucket. Better calibration means the cascade escalates the right hard cases to Opus, so cost scales with difficulty. The team warns the benchmark uses synthetic data (pseudopeople library from IHME) and results may not generalize directly to production.

C-3Firecracker VM Escape via KVM/EPT Memory Primitives — Full Guest-to-Host Root Execution

📰 Article (English)

Security researcher Paulos Yibelo (PWN Research) published "PwnEscape Part 2" — a full guest-to-host escape from a Firecracker microVM yielding root code execution on the host, while the guest VM stayed alive and SSH-accessible throughout. The attack builds on a host-memory read primitive from Part 1. The five-step chain: (1) Plant a nonce in a guest page; resolve the guest physical address (GPA) to a host physical address (HPA) by scanning Extended Page Table (EPT) roots. (2) Reverse-map the HPA through host page tables to find the Firecracker process's Page Global Directory (PGD). (3) Recover the binary's load bias under ASLR by validating known byte sequences. (4) Locate the vCPU's saved pt_regs frame for the thread blocked in KVM_RUN. (5) Overwrite the saved instruction pointer so that when KVM_RUN returns, Firecracker calls its own write() wrapper to emit a marker to stderr — then restore all modified stack words. A single byte written to serial port 0x3f8 triggers the vCPU exit. The lab setup used Firecracker v1.16.1 on x86-64, run directly as root with no jailer. Production deployments with the jailer, seccomp, and namespaces would materially change the blast radius and require separate assessment.
