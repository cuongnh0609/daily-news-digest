B1Snowflake Agent Identity徹底解説——AIエージェントを人間ユーザーと区別する認証・監査・ガバナンス設計

📰 本文 + 和越対訳

Finatextのエンジニアがまとめた本記事は、Snowflakeが2026年9月にリリースした「Agent Identity」機能群を解説している。問題の本質は、コーディングエージェントに人間ユーザーのAPIキーやPATをそのまま渡すと、エージェントの操作が人間の操作と区別できなくなり、エージェント固有の制御や監査ができなくなる点だ。Agent Identityは「Identify・Audit・Govern・Control」の4領域を提供する。IdentifyではIS_AGENT_ACTIVATED関数とSERVICE_AGENTユーザータイプで判定し、Auditではクエリ履歴やアクセス履歴にエージェント情報が記録される。Controlの「Restricted Session Scope（RSS）」はエージェントセッションに付与する権限を最小化する仕組みだ。認証方式はPKCEを用いたOAuthが推奨されており、IS_AGENTIC = TRUEのセキュリティ統合を作成してエージェント専用トークンを発行する。プロダクション環境でAIエージェントを安全に運用するための実践的なリファレンスとなっている。

Bài viết từ kỹ sư Finatext giải thích chi tiết tính năng "Agent Identity" của Snowflake, ra mắt tháng 9/2026. Vấn đề cốt lõi là khi cấp API key của người dùng cho AI agent, hành động của agent không thể phân biệt với người dùng thật, gây khó khăn cho audit và kiểm soát. Agent Identity cung cấp 4 lĩnh vực: Identify (hàm `IS_AGENT_ACTIVATED`, user type `SERVICE_AGENT`), Audit (ghi nhận agent info vào query/access history), Govern (masking policy theo agent activation), và Control (Restricted Session Scope — giới hạn quyền tối thiểu cho session agent). Phương pháp xác thực khuyến nghị là OAuth với PKCE, tạo security integration có `IS_AGENTIC = TRUE`. Đây là tài liệu tham khảo thực chiến cho việc vận hành AI agent an toàn trên môi trường production.

人間のキーを渡し続けずにいると、エージェントの追跡が困難になる。 Nếu tiếp tục không cấp key riêng cho agent, việc theo dõi hoạt động của agent sẽ trở nên khó khăn.

C2Docker Releases Open-Source "Docker Agent" — Declarative YAML Agent Builder with MCP, RAG, and Multi-Agent Orchestration

📰 Article (English)

Docker Engineering has open-sourced Docker Agent (Apache-2.0), a CLI plugin and runtime for building and running AI agents. Rather than writing agent logic in code, developers define agents in declarative YAML files specifying tools, memory, and behavior. Agents are invoked via docker agent, and they can delegate work to sub-agents for complex multi-agent setups. The runtime is model-agnostic: it supports OpenAI, Anthropic, Google Gemini, AWS Bedrock, Mistral, xAI, and Docker Model Runner (for local models). Any Model Context Protocol (MCP) server — local, remote, or Docker-based — can be attached as a tool. Built-in RAG support includes BM25, vector embeddings, hybrid search, and reranking. Memory and task-tracking tools are also provided out of the box. Agent configs are versionable YAML files that can be packaged and pushed to any OCI-compatible registry (e.g., Docker Hub), then pulled and run anywhere Docker runs. This enables agent distribution as first-class OCI artifacts — the same pattern developers already use for container images. Installation is available via Docker Desktop, Homebrew, or binary download. The project is early-stage (v0.x) but shows Docker's intent to position agent infrastructure as a natural extension of the existing container ecosystem.
