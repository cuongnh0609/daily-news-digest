C-03Prompt Injection in HTTP Headers: What 217 Million Web Responses Show About a Silent Attack Surface

📰 Article (English)

Researchers at Signals Corps analyzed 217 million HTTP responses to map a largely undocumented attack surface: prompt injection delivered through HTTP response headers. When an AI agent or LLM-powered tool fetches a URL and processes the response — including headers like X-Custom-Message, Server, or even Set-Cookie — an attacker controlling the server can inject instructions directly into the model's context. The study found thousands of live sites serving headers containing model-control keywords like "Ignore previous instructions," "You are now DAN," and "SYSTEM OVERRIDE." Unlike body-level prompt injection (which most RAG sanitization pipelines already address), header injection bypasses sanitization steps that strip or truncate HTML content before feeding it to the LLM. The researchers note that frameworks like LangChain and LlamaIndex do not sanitize header content by default when processing fetched URLs. Mitigations include explicitly stripping or blocklisting response headers before LLM ingestion, configuring agents to use a header-sanitizing proxy, and adopting a signed-context model that marks trust boundaries for fetched data.
