B1Agent Plugins 1.0.0 は何を標準化し、何を標準化しなかったのか——最小仕様の設計哲学を読み解く

📰 本文 + 和越対訳

2026年8月6日にOpenAI・Amazon・Cursor・GitHub・VS Code・Vercelらが共同でリリースした「Agent Plugins 1.0.0」は、AIエージェント間でスキルやMCPサーバー設定を共有するための最小仕様を定めた標準規格だ。その核心は、plugin.jsonマニフェスト、skills/フォルダ（Anthropicが定めたAgent Skills形式）、そしてmcp.jsonによるMCPサーバー設定のパッケージング方法を統一したことにある。MCPサポートはstdio・streamable-http・SSEの3トランスポートのみに限定し、セキュリティ面ではプラグインルート外へのパス参照禁止・リモートサーバーのHTTPS必須・認証情報の設定ファイル直書き禁止といった厳格な要件を設けている。一方、未標準化の領域も明確だ。フック、サブエージェント、ルール、マーケットプレイス配布、プラグインの読み込み戦略、認証情報管理などは意図的にスコープ外とされており、実装が各社間で固まるまで待つという設計思想が読み取れる。Claude Codeはこの規格に未参加だが、対応議論が始まっている。

"Agent Plugins 1.0.0" được OpenAI, Amazon, Cursor, GitHub, VS Code và Vercel cùng phát hành vào ngày 6/8/2026, là tiêu chuẩn tối giản để chia sẻ skills và cấu hình MCP server giữa các AI agent. Điểm cốt lõi là thống nhất cách đóng gói: file manifest plugin.json, thư mục skills/ (theo định dạng Agent Skills của Anthropic), và mcp.json cho MCP server. Hỗ trợ MCP giới hạn ở 3 transport: stdio, streamable-http và SSE. Về bảo mật, tiêu chuẩn nghiêm cấm tham chiếu path ra ngoài plugin root, bắt buộc HTTPS cho remote server và cấm nhúng thông tin xác thực vào file cấu hình. Ngược lại, nhiều thứ cố tình không được chuẩn hóa: hooks, subagents, rules, phân phối marketplace, chiến lược load plugin và quản lý credential — triết lý thiết kế là "chờ cho đến khi các implementation ổn định". Claude Code chưa tham gia tiêu chuẩn này nhưng đã có thảo luận.

📰 Article (English)

Built-in confidence scoring lets the device decide autonomously when to escalate to cloud services versus handle locally. Needle 2 runs completely offline, preserving privacy. Developers can fine-tune it for custom tool vocabularies on standard computers, enabling highly specialized deployments.

C3SQLite Compressed Text-History: 20MB of Raw Revisions Compressed to 80KB Using Cross-Version Redundancy

📰 Article (English)

Simon Willison published a prototype for storing document revision histories in SQLite in a dramatically more storage-efficient way than naive approaches. The core insight: rather than storing each revision as a separate full row, compress all prior versions together as a single JSON array and apply zlib or zstd compression to the entire blob at once. This exploits the high redundancy between adjacent document versions — most edits change only a small portion of a document — allowing the compressor to find repeated strings across all versions simultaneously. The results are striking: 1,000 simulated revisions of a document, producing 20.4MB of raw revision text, compressed down to just 80.3KB as a Zstandard-compressed JSON array. That is roughly a 250× compression ratio, orders of magnitude better than compressing each revision independently. The implementation uses two database columns: one for the compressed blob containing all prior versions, and one for timestamps stored as Unix integers. Willison also prototyped a ChunkedHistoryStore variant that splits the history into multiple rows with a maximum chunk size, reducing the cost of recompression when a new revision is added. The approach is particularly relevant for applications storing user-generated content with frequent edits, such as collaborative documents, code editors, or any system requiring audit trails — places where revision history storage costs can become surprisingly large at scale.
