B-01逆解析MCP「REA」をClaude Codeに隔離接続——安全設計とA/Bテストで見えた実態

📰 本文 + 和越対訳

Zennに投稿された検証記事では、約170個のツールを備えた逆解析専用MCPサーバー「REA」を Claude Codeに接続し、その効果と安全上の課題を実験した内容が紹介されている。 筆者はREAを通常の開発環境や常駐ボットから切り離し、検証専用ディレクトリの.mcp.jsonにのみ登録した。 副作用を持つ43個のツールはdenyルールで機械的に遮断し、Node.jsは公式ビルドを版固定で分離配置した。 A/B試験では、REAの有無で回答精度に差はなかった一方、使用時は処理時間が最大2倍・費用が最大1.67倍に増加した。 広範な逆解析依頼はモデルの安全フィルタで止められるため、静的解析に絞ると実用的という結論が得られた。 標準ツールとgrepによる探索で十分なケースが多く、MCPの追加には費用対効果の見極めが必要と筆者は述べている。

Một bài viết thực nghiệm trên Zenn mô tả việc kết nối MCP server chuyên dùng reverse engineering "REA" với Claude Code trong môi trường cô lập. REA có khoảng 170 tool, nhưng tác giả chỉ đăng ký trong thư mục kiểm thử riêng và chặn 43 tool có side-effect bằng deny rule. Kết quả A/B test cho thấy độ chính xác không khác biệt, nhưng thời gian xử lý tăng tối đa gấp đôi và chi phí API tăng 1,67 lần. Các yêu cầu reverse engineering diện rộng bị model's safety filter chặn, nên chỉ hữu ích cho static analysis. Tác giả kết luận rằng trong nhiều trường hợp, standard tools và grep là đủ, và cần cân nhắc cost-effectiveness trước khi thêm MCP.

C-01How the Claude Code Team Reinvented Code Review — Layered AI Checks, Risk-Based Approval, and a Three-Round Cap

📰 Article (English)

The Claude Code team at Anthropic has published their internal code review approach, which represents a fundamental shift: the goal is now the least human review time that does not increase reverts or incidents. Between June and September, merged PRs more than doubled while the revert share fell by over 40%. The system runs in layers. Before a PR is opened, Claude runs tests, builds, and linters, and a subagent reviews the diff in a fresh context so it shares no assumptions with the code author. Recurring findings are addressed at the source through CLAUDE.md (project conventions) and REVIEW.md (per-directory review priorities). On every PR, parallel agents hunt for bugs while verifier agents vote on each finding — only confirmed findings reach the author, tagged as Important, Nit, or Pre-existing. Substantive review comments rose from 16% to 54% of all comments. Approval tiers are risk-based: a classifier assigns each PR to no-human, one-person, or two-person review. Billing paths, the auto-updater, and CI workflows always require a person; an agent's approval never counts as human. To stop infinite review loops, a three-round cap was added and diff-only re-review was required, cutting the mean reviews-to-pass from 2.08 to 1.32. Past incidents form an eval set run daily against reviewer improvements.
