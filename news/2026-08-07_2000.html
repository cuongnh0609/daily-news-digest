📰 本文 + 和越対訳

法務省は2026年8月7日、生成AIを使って特定の人物の声を無断で複製・使用する行為が、民事上の権利侵害に当たるとする解釈指針を公表した。声は氏名や肖像と同様に「個人識別情報」として位置づけられ、パブリシティ権や人格権の保護対象となる。具体的には、声優の声を学習させたAIで歌声動画を収益化するケースや、著名人の音声を使ったディープフェイク音声などが違法となりうる。さらに特定の声優の声を再現するAIツールを提供する事業者も、パブリシティ権侵害の責任を問われる可能性があると明示された。今回の指針は法的な強制力を持つ法令ではないが、裁判所の判断に影響を与えることが予想される。

Bộ Tư pháp Nhật Bản ngày 7/8/2026 công bố hướng dẫn giải thích luật, khẳng định rằng việc sử dụng giọng nói của người khác mà không có sự đồng ý thông qua AI tạo sinh là hành vi xâm phạm quyền dân sự. C3Inside vLLM: Anatomy of a High-Throughput LLM Inference System

📰 Article (English)

A deep technical analysis of vLLM — the open-source inference engine that has become the de facto standard for serving large language models at scale — reveals the elegance of its core architecture. At its heart, vLLM introduces PagedAttention, which organizes key-value (KV) cache memory into fixed-size blocks modeled after OS virtual memory management, enabling efficient memory reuse across concurrent requests and virtually eliminating memory fragmentation. The engine achieves high throughput through continuous batching, processing new incoming requests alongside existing in-flight ones rather than waiting for full batch completion. A sophisticated scheduler manages both the compute-intensive prefill phase (processing the input prompt) and the bandwidth-limited decode phase (generating tokens one by one), using chunked prefill to prevent long prompts from monopolizing GPU resources and starving other requests. Additional optimizations include speculative decoding (generating multiple tokens per step using a smaller draft model), prefix caching (reusing KV cache for repeated system prompts), and support for tensor parallelism and data parallelism for multi-GPU and multi-node deployments. The analysis shows that vLLM fundamentally improves the throughput-latency tradeoff compared to naive implementations, enabling providers to serve significantly more concurrent users at lower response times.

Một scheduler tinh vi quản lý cả giai đoạn prefill (tốn nhiều compute để xử lý prompt đầu vào) lẫn giai đoạn decode (sinh từng token một, bị giới hạn bởi băng thông), dùng chunked prefill để ngăn prompt dài chiếm toàn bộ GPU và làm đói các request khác.
