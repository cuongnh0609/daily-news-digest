B1GPT-6 Astraのasync tool callingとmid-turn steeringを実測——名前通りに動かない2機能の真相

📰 本文 + 和越対訳

OpenAIのGPT-6 Astraに新たに搭載された「async tool calling」と「mid-turn steering」という2つの機能を実際に計測・検証した記事が話題を呼んでいる。async tool callingは、tool callの結果を待たずにモデルが次の応答を生成し続ける仕組みだが、実測では応答コストが20〜30%増加し、処理時間も3〜4秒長くなることが判明した。一方でtoolの遅延が大きい場合には独立した回答を先に返せる利点もある。mid-turn steeringはWebSocket経由で応答生成中に追加の指示を送り込む機能だが、現在の出力アイテムが完了するまで新指示は適用されない。著者はいずれの機能も「名前から想像する動作と実装に乖離がある」と指摘し、エージェント設計においては実装の詳細を正確に把握することの重要性を強調している。

Một bài viết kỹ thuật chi tiết về hai tính năng mới của GPT-6 Astra — "async tool calling" và "mid-turn steering" — đang thu hút sự chú ý. Qua thực đo, async tool calling làm tăng chi phí response 20-30% và kéo dài xử lý 3-4 giây, dù có ưu điểm trả lời các câu hỏi độc lập sớm hơn khi tool có độ trễ cao. Mid-turn steering (gửi thêm chỉ thị qua WebSocket khi đang sinh response) chỉ được áp dụng sau khi output item hiện tại hoàn thành. Tác giả kết luận rằng cả hai tính năng đều "hoạt động khác với cái tên gợi ý", và việc hiểu chính xác chi tiết implementation là điều cốt yếu trong thiết kế agent.

複数のClaude Codeインスタンスを同時に稼働させる並列開発ワークフローとして、Herdr・git worktree・Claude Codeの組み合わせが注目を集めている。同一ディレクトリで複数エージェントを動かす場合、ブランチ切り替えが全エージェントに影響してしまう問題が生じる。これを解決するのがgit worktreeで、同一の`.git`ディレクトリを共有しながら複数の作業ディレクトリを作成できるため、ブランチの競合なしに並列作業が可能になる。Herdrは各エージェントの状態をサイドバーに表示するRust製のターミナルマルチプレクサで、Claude CodeのAgent Skillと連携してworktreeの自動作成・管理を担う。SessionStartフックを活用すれば「リポジトリ1つにつき1画面、横に並べたworktree」という環境が自動で整備され、並列開発の効率が大幅に向上するとの報告がある。

C1Real-SWE: Benchmarking AI Coding Agents on Private, Real-World Enterprise Codebases

📰 Article (English)

Specific Labs has released Real-SWE, a benchmark that evaluates frontier AI coding agents on actual production codebases from real companies — not curated open-source repositories. Tasks span multiple files (median 11 files) with brief, business-realistic instructions (median 1,742 characters), requiring agents to understand company-specific patterns and business logic in isolated sandboxes with real tools: AWS emulators, Docker, Kubernetes, Slack, and GitHub. Results reveal a significant gap between lab benchmarks and production reality. Anthropic's Fable 5.1 led with 38.8% task resolution, followed by GPT-6 Astra at 33.8% and Gemini 3.8 Flash at 31.2%. Crucially, six of ten sample tasks had resolution rates below 15%, and one task ("Analytics stream reducer") showed 0% across all models tested. The most common failure mode was "missed requirements," followed by integration errors and unverified assumptions. A striking cost-performance finding: Gemini 3.8 Flash achieved competitive results at $2.50 per rollout versus Fable 5.1 at $6.96. Notably, 71.4% of rollouts completed in under 10 minutes failed, suggesting complex enterprise tasks genuinely require extended agent reasoning time — a signal that speed-optimized deployments may underperform in production.

📰 Article (English)

GitHub has released REST API endpoints in public preview for programmatically managing its AI Scan for pull requests feature across organizations and repositories. The new endpoints — /orgs/{org}/code-scanning/ai-scan and /repos/{owner}/{repo}/code-scanning/ai-scan — allow teams to read and toggle whether AI-powered security scanning is enabled at both organization and repository levels. The hierarchical permission model is worth understanding: organization-level settings govern whether AI Scan can operate across the organization at all, while repository-level settings control individual repos. Critically, a repository cannot enable AI Scan if the organization has disabled it — making org-level governance the authoritative control point for enterprises managing AI security at scale. This feature is exclusively available to GitHub Advanced Security customers on github.com, with no GitHub Enterprise Server support currently. The primary benefit is enabling DevSecOps teams to roll out AI-powered security detections to select repositories programmatically — eliminating manual, per-repo UI configuration that becomes impractical at scale. Combined with GitHub Actions, teams can build automated onboarding pipelines that enable AI security scanning as part of repository provisioning workflows.

C3GPT-6 Astra Generates Running Routes via OSM — But Code Auditability Remains a Blind Spot

📰 Article (English)

Simon Willison documents using GPT-6 Astra (Max tier) with ChatGPT Work to generate 5K and 10K running loop routes from his home address. The agent used Nominatim to geocode the address and Overpass API to download local OpenStreetMap roads and trails, then computed loop routes locally — delivering results within 27 minutes including an interactive D3.js visualization and downloadable GPX and GeoJSON files. The technical pipeline is genuinely impressive: the system assembled, ran, and iterated on Python geospatial code autonomously, producing usable fitness routes without manual intervention. The visualization used D3.js with geometry embedded as JSON inside HTML, respecting a Content Security Policy that restricted external resources to specific CDNs. However, Willison highlights a significant auditability gap: the Python code the agent ran was never visible in the ChatGPT interface. After thread compaction, the system could not retrieve the code at all. He argues this is a design failure — agent systems should expose pre-compaction conversation text through tool calls, and generated code should always be surfaced to users who want it. As AI agents become practical for everyday tasks, the gap between "it worked" and "I can see what it did" is becoming a genuine engineering concern.
