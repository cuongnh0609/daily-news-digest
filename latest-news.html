B1OpenTelemetry×Cloudflareで組織のClaude Code利用ログを収集する

📰 本文 + 和越対訳

Gemcook のテックリードが、Claude Code の OpenTelemetry（OTel）サポートを活用し、組織全体の利用ログを Cloudflare Workers と R2 だけで収集するアーキテクチャを公開した。従来の ccusage コマンドはメンバーが各自で実行する必要があり、長期的な組織横断の監視には向かなかった。OTel は設定を配布するだけで自動的にテレメトリが送信されるため、チーム全体への展開が容易になる。api_request イベントには、ユーザーのメールアドレス、セッションID、使用モデル、入出力トークン数、推定コスト、実行時間などが含まれる。バックエンドは OTel Collector を使わず、http/json でペイロードを受け取り、Cloudflare Workers で処理して R2 に生データを保存するシンプルな構成だ。配布は server-managed settings で一括できる。ただし、収集内容と目的の事前周知、プライバシーへの配慮、一部設定で意図しない情報が送信される点など、運用上の注意事項も詳しく解説されている。可視化と集計については続編記事が予定されている。

Tech Lead tại Gemcook đã công bố kiến trúc thu thập log sử dụng Claude Code trên toàn tổ chức bằng cách tận dụng hỗ trợ OpenTelemetry (OTel) của Claude Code kết hợp với Cloudflare Workers và R2. Không giống ccusage vốn đòi từng thành viên tự chạy lệnh, OTel chỉ cần phân phối cấu hình là tự động gửi telemetry, giúp triển khai toàn đội dễ dàng hơn. Sự kiện `api_request` chứa email người dùng, session ID, model sử dụng, số token vào/ra, chi phí ước tính và thời gian thực thi. Backend không dùng OTel Collector mà nhận payload qua `http/json`, xử lý bằng Cloudflare Workers và lưu raw data vào R2. Việc phân phối cấu hình được thực hiện qua server-managed settings. Bài viết cũng lưu ý quan trọng về việc thông báo trước cho thành viên về nội dung thu thập, bảo vệ quyền riêng tư, và một số cấu hình có thể gửi thông tin ngoài ý muốn.

C1External Sandboxes for Coding Agents — A New Pattern for Safe Code Execution

📰 Article (English)

Simon Willison and Prime Radiant published a detailed write-up on "external sandboxes" — a new architectural pattern designed to let coding agents execute code safely, particularly useful when running local or less-trusted models. The core idea separates where the agent runs from where code executes: the agent itself runs in the normal environment, but any code it generates is sent to a separate sandbox for execution. Three open-source reference implementations were released, each exposing the same localhost API: external-sandbox-v86 (runs Alpine Linux in WebAssembly via v86 for maximum portability), external-sandbox-container (uses Apple Containers for macOS users), and external-sandbox-quicksand (wraps Microsoft's Quicksand QEMU-based library). The sandboxes include an optional HTTP/HTTPS allow-list proxy to control which hosts sandboxed code can reach, plus a credential replacement mechanism that lets agents make authenticated API calls without ever seeing the secret. A network policy UI provides real-time visibility into proxy rules and recent activity. Claude Code, Codex, and Pi can all be pointed at the sandbox API. This pattern directly addresses prompt injection risks and accidental system damage from agent-generated code.

📰 Article (English)

Runta published FrontierHarness Eval v1.1, a large-scale benchmark comparing 22 agent harness configurations across 5 open LLMs on 62 terminal tasks — totaling 27,280 agent runs and 83 billion tokens, 76 times larger than v1.0. The key finding: the model explains 92.8% of cost variation (by two-way ANOVA), while the harness choice explains only 2.3%. This overturns a common assumption that harness selection has major cost or performance implications. Each model had a different best harness on the pass-rate-versus-cost metric — Codex CLI ranked 1st with GLM-5.3 but 16th with Kimi-K3. Higher cost per task did not correlate with higher pass rates (rank correlation -0.39 to +0.22 across models). Number of steps was the best predictor of cost per pass (rank correlation +0.51). The benchmark flagged 216 trials for reward hacking — 163 were online lookups — all scored zero. Closed models including Claude Opus 5.5 are planned for v1.2. The results have significant implications for teams optimizing agent infrastructure: spend on model selection, not harness optimization.
