C1Building a Multi-Agent System from Scratch: Architecture Patterns That Actually Hold in Production

📰 Article (English)

Engineer Kadharmoideen Fadurudeen published a detailed technical breakdown of three multi-agent architecture patterns and the failure modes that only emerge outside of demos. The core insight is that multi-agent systems add a coordination problem on top of the reasoning problem, and most engineering effort should go into coordination design. The three patterns covered are: orchestrator-worker (a central orchestrator breaks tasks into subtasks sent to specialized workers — best when decomposition is clear upfront), blackboard (agents read and write shared state and decide when to contribute, guided by a lightweight scheduler — best when the solution path can't be known in advance), and pipeline (a fixed sequence of agents each passing output to the next — easiest to evaluate but rigid). The post provides a clear selection rule: use a pipeline if the steps can be written as a checklist upfront; use orchestrator-worker if the steps are known but their details depend on input; use a blackboard if the path can only be discovered during execution. Failure modes discussed include infinite delegation loops, runaway cost from repeated model calls, conflicting concurrent writes to shared state, and error propagation where one agent's hallucination compounds downstream. The author recommends hard caps on delegation depth (3–5 hops), a centrally tracked token budget per task with a hard stop, and a defined human escalation path when confidence is low.
