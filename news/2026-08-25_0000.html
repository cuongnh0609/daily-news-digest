B-1デザイナーが主導する仕様駆動型デザインシステム——Figma MCP × Claude Codeでコンポーネント生成を自動化

🇯🇵 日本語 + 🇻🇳 Bản dịch

Zennに投稿されたこの記事は、フロントエンドエンジニアの工数に頼らずデザイナー単独でReactコンポーネントを生成するパイプラインの構築事例を詳述している。アプローチの核心は「コンポーネントスペック」と呼ばれるYAMLベースの仕様書で、Figma MCPによるデザイン構造の抽出・Radix UIのアクセシビリティ仕様・デザイナーが手書きした利用原則の三者を一つのドキュメントに統合する。Claude Codeはこのスペックを読み込み、実装コード・Storybookドキュメント・テストを一括して自動生成する。検証の結果、単一ファイルによるSSOT（Single Source of Truth）より「責務ごとに分割した仕様管理」の方が現実的と判明した。エンジニア不在でもデザインシステムの一貫性を保てることを実証した点で、仕様駆動開発（Spec-Driven Development）の具体的な実装例として注目される。

Bài viết trên Zenn mô tả quy trình cho phép designer tự tạo React component mà không cần nhờ frontend engineer. Cốt lõi là tài liệu "Component Spec" dạng YAML, tích hợp ba nguồn: cấu trúc design từ Figma MCP, đặc tả accessibility từ Radix UI, và nguyên tắc sử dụng do designer viết tay. Claude Code đọc spec này và tự động sinh ra code implement, tài liệu Storybook, và test một lần. Thực nghiệm cho thấy quản lý spec theo từng trách nhiệm riêng biệt hiệu quả hơn file SSOT đơn lẻ. Đây là ví dụ thực tế điển hình của Spec-Driven Development với AI, nơi AI agent thực thi kế hoạch từ đặc tả có cấu trúc.

B-2AI Agentに社内知識をオンボーディングする——SkillsとEvalの設計で正解率96%を達成

🇯🇵 日本語 + 🇻🇳 Bản dịch

Nghiên cứu đăng trên Zenn định lượng hóa cách cung cấp kiến thức nội bộ cho AI agent ở trạng thái "nhân viên mới chưa được onboard". C-2Why Your Local LLM Feels Dumber Than It Is — Quantization, Attention Backends, and KV Cache Are the Culprits

🌐 English

A detailed technical investigation on the Level1Techs forum explains why locally-run LLMs consistently underperform against cloud-hosted reference implementations, even with identical model weights. The root cause is not the model itself but the accumulated divergence across four layers of the inference stack. KV Cache Quantization: reducing key-value cache precision from BF16 to INT4 causes cascading errors in long contexts, with INT4 producing irreversible tool-call failures in testing. Attention Backend Selection: FlashAttention 2, Flash Inference, and Triton kernels produce measurably different token predictions, particularly on later parts of long prompts. Weight Quantization: NVFP4 implementations showed approximately 50% token disagreement at 88K context length versus BF16 baseline. Tensor Parallelism: splitting computation across multiple GPUs via NCCL introduces additional divergence sources. The author recommends using workload-representative benchmarks, following model-specific sampler configurations, and using 100% sample rate evaluation of full logit distributions when testing critical tool-calling workflows.

C-3Your Executable Is a SQLite Database — A New Technique for Packaging Binaries as Queryable Databases

🌐 English

Simon Willison reports on Farid Zakaria's proof-of-concept that embeds an ELF executable directly inside a SQLite database file. The trick exploits the SQLite application ID field (at byte offset 68) by setting it to "SELF" — a magic string that signals a custom binfmt_misc kernel handler. The binary's structural components (code segments, headers, dependencies) are stored in SQLite tables following a defined schema. At runtime, the self-exec interpreter extracts these components and executes them. The result is a file that works simultaneously as both a valid SQLite database and a runnable ELF binary. This enables developers to inspect, query, patch, and even compose executable logic using standard SQL. Practical implications include unified data-and-code distribution packages, SQL-queryable binary introspection ("SELECT * FROM sections WHERE name='.text'"), and novel versioning approaches where program components are rows. While currently a Linux-focused proof of concept, the technique highlights how SQLite's ubiquity and binfmt flexibility combine to enable surprising new patterns.
