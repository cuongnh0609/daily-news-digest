C-01Cerebras Deploys Trillion-Parameter AI Models via 59-Wafer Pipeline — 1000+ Tokens/Sec at Scale

📰 Article (English)

Cerebras has published a detailed technical breakdown of how it serves frontier-scale models — like Kimi K3, a roughly 3-trillion-parameter mixture-of-experts model — at production speeds exceeding 1,000 tokens per second. The fundamental challenge is that no single wafer-scale chip (WSE-3T at 44 GB) is large enough to hold a frontier model's weights, which run into terabytes. Cerebras's solution is model pipeline parallelism across roughly 59 wafers: each wafer holds a fixed slice of layers, and activations flow sequentially from one wafer to the next while each stage simultaneously processes different requests, achieving high throughput through overlapping computation. Unlike tensor parallelism (which requires all-reduce communication between chips at every layer), this pipeline approach keeps chips mostly independent, meaning inter-chip communication is cheap — just passing activations between stages. The result is that a model requiring terabytes of memory can run at speeds that match or exceed single-chip inference for smaller models. Cerebras claims the architecture can scale linearly as more wafers are added. This is a significant data point for the inference infrastructure landscape: it demonstrates that trillion-parameter open-weight models (Kimi K3, Llama 4 Scout, etc.) are deployable at cost-competitive speeds today.

C-03AI Is Getting Good at Math — How Drafter-Solver-Verifier Loops Are Cracking Hard Problems

📰 Article (English)

A recent analysis from Latent Space argues that AI models are now genuinely good at mathematics — not because they've memorized more proofs, but because modern systems combine parallel search, automated verifiers, and iterative feedback from failed attempts in a way that structurally mirrors how human mathematicians work on hard problems. The key insight is that difficulty scales with two factors: how many "key insights" a problem requires, and how wide the search tree is at each decision point. For problems where the solution space is narrow (a well-defined target shape), models can exhaustively explore with compute instead of intuition. The proposed engineering pattern — drafter generates a candidate, verifier rejects it with a constraint, solver re-searches with that constraint applied — creates a feedback loop that turns failed proofs into stepping stones. This is already being applied beyond pure math: security proofs for open-source libraries, formal verification of protocol implementations, and automated theorem-proving for compiler correctness. For software engineers, the takeaway is concrete: if your domain has a formal verifier (type checker, test suite, proof assistant, linter), you can replicate this pattern. Build a harness where Claude drafts, your verifier rejects with structured feedback, and Claude re-drafts using the constraint — the loop dramatically outperforms single-shot generation on hard specifications.
