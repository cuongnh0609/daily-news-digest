C1MCP 2.0 Goes Stateless: The Most Significant Protocol Change Since Launch

📰 Article (English)

The Model Context Protocol (MCP) has undergone what Simon Willison calls "the most significant change since it first launched" — moving from a stateful, session-based architecture to a fully stateless HTTP design. Previously, building an MCP client required two round-trips: a session initialization call that returned a session ID, followed by the actual tool call. The new stateless spec collapses this into a single HTTP request using headers like MCP-Protocol-Version and Mcp-Method, eliminating server-side session management entirely. This shift has major implications for both client and server implementers. Servers no longer need to track session state, making deployments simpler and dramatically easier to scale horizontally. Smaller local models can now drive MCP tools without the overhead of session negotiation. Willison released two practical tools to demonstrate the value: mcp-explorer, an interactive CLI for probing MCP servers, and datasette-mcp, which exposes a Datasette database as queryable MCP tools. The stateless approach also improves security posture. Unlike shell-level agents with unrestricted curl access, MCP tools form a well-defined, auditable surface — easier to review for prompt injection and data exfiltration risks. For teams running sensitive workloads, MCP now represents a more responsible path to agentic AI integration than raw shell execution.
