📰 本文 + 和越対訳

MicrosoftのAIエージェント開発用SDK「Microsoft Agent Framework」のPythonパッケージが第三者に侵害され、認証情報を窃取する不正バージョンが一時的にPyPI上で公開された。問題のバージョンは1.26.1と1.26.2で、11月17日（UTC）に公開された後、発見次第削除された。正規版の1.26.0以前は影響を受けない。不正版はPythonの起動時に自動で読み込まれる「.pth」ファイルを悪用し、インストールするだけで動作する仕組みを持っていた。標的となった認証情報はAzure、AWS、GitHub、OpenAIなどのアクセストークンや環境変数で、これらを外部のwebhook.siteへ送信していた。バージョン1.26.2ではGitHub Actionsのトークンも収集対象に加わった。PyPIが1.26.1を隔離してから約2分後に攻撃者が1.26.2を公開する素早い動きも確認されており、サプライチェーン攻撃の高度化を示している。米GitHub Advisory Databaseは、影響を受けた環境では認証情報が漏えい済みとみなし、アクセス可能なすべての認証情報を即座に再発行するよう求めている。

Các phiên bản có vấn đề là 1.26.1 và 1.26.2, được đăng vào ngày 17 tháng 11 (UTC) trước khi bị xóa. Phiên bản độc hại lợi dụng file ".pth" tự động tải khi Python khởi động, thu thập access token của Azure, AWS, GitHub, OpenAI và gửi ra ngoài qua webhook.site. GitHub Advisory Database khuyến cáo coi tất cả thông tin xác thực trong môi trường bị ảnh hưởng là đã bị rò rỉ và cần tái tạo ngay lập tức.

C2Inkling 2 Mini: Open-Weights Looped MoE Model Hits 79% SWE-bench, Runs in ~20GB Memory

📰 Article (English)

Thinking Machines Lab has released Inkling 2 Mini, an open-weights model that applies a novel "looped transformer" architecture to run its middle layers three times per token rather than once. The result is a model that reasons more deeply without generating more output tokens, hitting 79.2% on SWE-bench Verified (bash only) — leading all open-weights models under 100B total parameters on agentic coding tasks. The architecture is a Mixture-of-Experts model with 26.4B total parameters and 3.4B active parameters per token. The model was pruned from a larger training run: two-thirds of its experts were removed and the remaining ones were healed using distillation. Most weights are stored in NVFP4 (20 of 24 layers), with the last four layers in MXFP8, requiring approximately 20GB of memory in total. It runs on Ollama, vLLM, SGLang, llama.cpp (GGUF format), and Thinking Machines' own Tinker runtime. The team also released a research variant, TML-d24-varloop-research, used to study the monitorability of looped transformers — an alignment-relevant property. Weights are on Hugging Face. The release also includes scores on SWE-bench Pro v2 Hard (77.9%), DeepSWE v1.1 (48.2%), and the Vals Index v2.2 (46.5%). The model is noted to be weaker on multi-turn conversation, complex constraint tasks, and knowledge-intensive questions.

C3The War Against AI Slop: Formal Verification Emerges as a Practical Weapon for Developers

📰 Article (English)

Richard MacManus, writing for Latent Space, argues that formal verification — mathematically proving that software does exactly what its specification requires — is becoming a practical response to "slop," the low-quality AI-generated code that defined much of 2026. As LLMs generate more code at higher speed, the ability to verify correctness mathematically rather than test empirically is becoming a competitive advantage. Several startups are building in this space. &Truth, co-founded by Clark Barrett (co-creator of the SMT solver cvc5), is building a "verification machine" on top of Lean, a proof assistant. Its first product, &Atlas, maps open-source C code for formal verification. Barrett notes that cvc5 is already used heavily inside Amazon, including in Kiro, the new spec-driven AI development tool. Harmonic's Aristotle has AI write proofs that Lean then checks. Axiom Math uses formal verification as training feedback for its math models via AxiomProver and AXLE. Anthropic has described a pattern of "LLM-scaled formal verification," with Opus 5.5 reaching a 50% solve rate on 36 small verification tasks using about 40% fewer tokens than the previous model. The article's main prediction is that developers will shift toward "veri-coding" — spending more time writing precise specifications and less time reviewing AI-generated diffs. This aligns with the broader spec-driven development trend.
