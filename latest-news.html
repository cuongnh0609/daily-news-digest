B-1Claude Codeのハーネスを自己改善させる——PR後の手直しをルール・スキル・フックに自動フィードバックするループ設計

本文 / Nội dung

Zennにて、AIエージェントが生成したPR（プルリクエスト）にマージ前に人間が加える「手直し」を、Claude Codeのハーネス（ルール・スキル・lintなど）へ自動的にフィードバックするループの実装例が公開された。筆者は設計から実装・検証・PR作成まで全フローをAIに委ねているが、命名規則の揺れやUI文言の細かな変更など、同じ種類の手直しが繰り返されることに気づいた。そこで、AIコミットには追跡用トレーラーを付与し、PR後の手修正コミットをgit履歴から機械的に抽出。各手直しを「ルール・スキル・lint・テスト・要件」のどれで防げるかを別エージェントが判定し、防げないものは除外。採用された改善案はPostToolUse hookなどに1コミット1提案の粒度で反映される。この仕組みにより、人間が見るべき領域を「要件の曖昧さ」と「判断」に絞り込みながら、機械的に防げるミスの範囲を継続的に広げていくことができる。

Một bài viết trên Zenn giới thiệu thiết kế vòng lặp tự cải thiện harness của Claude Code. Tác giả để AI đảm nhận toàn bộ quy trình từ thiết kế, implement, kiểm thử đến tạo PR, nhưng nhận thấy cùng một loại chỉnh sửa tay (đặt tên biến, văn bản UI...) cứ lặp đi lặp lại trước khi merge. Giải pháp: gắn trailer theo dõi vào commit của AI, sau đó tự động trích xuất các commit sửa tay từ git history. Một agent riêng phân loại xem mỗi lần sửa có thể ngăn chặn bằng rule, skill, lint, test hay yêu cầu không, loại bỏ những gì không tự động hóa được. Các đề xuất cải tiến được áp dụng vào PostToolUse hook với cấu độ 1 đề xuất/1 commit. Kết quả là phạm vi lỗi được ngăn chặn tự động mở rộng dần, trong khi con người chỉ cần tập trung vào quyết định và yêu cầu còn mơ hồ. Đây là ví dụ thực tế về agentic engineering trong môi trường sản xuất.

B-3MCPクライアントがOAuthでMCPサーバーにつながる仕組み——CIMD・DCR・保護リソースメタデータを徹底解説

本文 / Nội dung

ZennにてMCPクライアントがOAuthでMCPサーバーへ接続する仕組みを詳しく解説した記事が公開された。接続には「認可サーバーの発見」と「クライアントの識別」という2つの課題がある。認可サーバーの発見では、MCPサーバーが401応答と保護リソースメタデータ（RFC 9728）で認可サーバーの場所を示し、クライアントはそこからRFC 8414のメタデータを取得してログイン先やトークン発行先を知る。クライアント識別には事前登録・DCR（動的登録）・CIMD（HTTPSメタデータURLをclient_idとする方式）の3方式があり、MCP仕様2026年7月版ではDCRが非推奨となりCIMDが推奨されている。接続時はPKCEと認可コードフローでトークンを取得し、resourceパラメータで対象のMCPサーバーを指定する。Better AuthはCIMDと発見に対応済みで、Supabaseは発見に対応したもののDCRを案内している状況など、実装の現在地も紹介されている。

Một bài viết chi tiết trên Zenn giải thích cơ chế MCP client kết nối với MCP server qua OAuth. Có hai thách thức: "khám phá authorization server" và "nhận diện client". Để khám phá auth server, MCP server trả về 401 kèm Protected Resource Metadata (RFC 9728), client dùng thông tin đó để lấy Authorization Server Metadata (RFC 8414) và biết endpoint đăng nhập/cấp token. Để nhận diện client, có 3 phương thức: đăng ký trước, DCR (dynamic registration), và CIMD (dùng HTTPS metadata URL làm client_id). Spec MCP tháng 7/2026 đã deprecate DCR và khuyến nghị CIMD. Khi kết nối, token được lấy qua PKCE + authorization code flow, với tham số resource chỉ định MCP server mục tiêu. Better Auth đã hỗ trợ CIMD và discovery, trong khi Supabase hỗ trợ discovery nhưng vẫn hướng dẫn DCR.

Content (EN)

A critical Linux kernel vulnerability dubbed PwnEscape (CVE-2026-99999, CVSS 9.3) has been disclosed via the Openwall oss-security mailing list. The flaw, classified as a "Guest-to-Host KVM Escape," resides in the kernel's network packet processing code. An attacker can overwrite checksum metadata for IPv4 headers that the kernel has already verified, disrupting normal memory handling and ultimately achieving code execution on the hypervisor host from within a guest virtual machine. The research team demonstrated the attack in a controlled lab environment and predicts that working exploits for weaker configurations will emerge within weeks, with default hypervisor setups potentially exploitable within a month. In Japan, Sakura Internet has already paused new sign-ups for VPS and rental server plans while it applies countermeasures. AWS has confirmed that managed services (EC2, Lambda, Fargate) are unaffected and has released a patched Amazon Linux 2 update. Linux distributions including Ubuntu and RHEL are expected to publish backported fixes shortly.
