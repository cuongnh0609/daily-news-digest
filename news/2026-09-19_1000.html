06AIへの「念のためプロンプト」はもう逆効果——Claudeのトークンを浪費する6つのアンチパターン

📰 本文 + 和越対訳

ITmedia/@ITに掲載されたエンジニア向けの解説記事が、Claude利用時にやりがちな「6つのアンチパターン」を具体例つきで紹介し、大きな反響を呼んでいる。記事が指摘する代表的な問題は「念のためプロンプト」——本来必要のない確認指示や過剰な制約を追記することで、トークン数が不必要に膨らみ、モデルの推論品質が下がるという逆説的な現象だ。他にも「毎ターン同じコンテキストを再送信する」「エラー処理の指示を細かく書きすぎる」「出力形式を曖昧なままにする」といったパターンも取り上げられている。解決策として記事は、プロンプトを「必要十分」に絞り込み、cache-controlでシステムプロンプトを再利用すること、またモデルの推論ステップを信頼して中間工程への過干渉を避けることを推奨している。Claude利用コストが問題になりやすいチームには特に実践的な内容だ。

08「Java 27」正式リリース——全環境でG1 GCがデフォルトに、耐量子暗号のハイブリッドキー交換も搭載

📰 本文 + 和越対訳

Oracleは9月15日、Java 27を正式リリースした。今回のリリースで最大のアーキテクチャ上の変更は、あらゆる実行環境においてG1 GC（ガベージコレクター）がデフォルトガベコレとなった点だ。これにより従来のParallel GCがデフォルトだった環境でも、自動的にG1に切り替わるため、既存アプリケーションのGCチューニングを見直す必要が生じるケースがある。セキュリティ面では、NIST承認の耐量子暗号アルゴリズムと従来のECDHを組み合わせたTLS 1.3用ハイブリッドキー交換が実装され、量子コンピュータの脅威に対する前方秘匿性の強化が図られた。また、仮想スレッドの安定化やRecord Patternsの改善など、Project Loomおよび関連JEPの成果も取り込まれている。エンタープライズ向けのJava環境を運用するSREには要注意のアップデートだ。

Oracle đã phát hành Java 27 chính thức vào ngày 15 tháng 9. Thay đổi kiến trúc lớn nhất trong lần phát hành này là G1 GC (Garbage Collector) trở thành garbage collector mặc định trong mọi môi trường thực thi. Do đó, ngay cả trong các môi trường mà Parallel GC là mặc định trước đây cũng sẽ tự động chuyển sang G1, nên có thể phát sinh trường hợp cần xem xét lại GC tuning của các ứng dụng hiện có. Về mặt bảo mật, hybrid key exchange cho TLS 1.3 kết hợp thuật toán mã hóa kháng lượng tử được NIST phê duyệt với ECDH truyền thống đã được triển khai, nhằm tăng cường forward secrecy trước mối đe dọa từ máy tính lượng tử. Ngoài ra, cũng đã tích hợp kết quả của Project Loom và các JEP liên quan như ổn định hóa virtual threads và cải thiện Record Patterns. Đây là bản cập nhật mà các SRE vận hành môi trường Java dành cho doanh nghiệp cần chú ý.

11GitHub Copilot Code Review Gets Smarter: Progress Tracking, Auto-Resolution, and Contextual Commit Messages

📰 Article (English)

GitHub has shipped three major improvements to its Copilot code review feature, now generally available as of September 18. First, the overview comment now categorizes findings into structured buckets: "Open" (unaddressed issues), "Resolved since last review" (fixed items), and "Previously missed" (newly detected existing issues). Each finding includes severity levels and direct links to the relevant code lines. Second, Copilot now intelligently auto-resolves its own comments based on subsequent commits — if a developer replies to explicitly keep an issue open, the system honors that signal. Auto-resolved comments are marked either "Won't Fix" or "Incorrect" to preserve transparency. Third, when accepting multiple Copilot suggestions in batch, the tool now auto-generates contextual commit titles and descriptions, including non-Copilot comments in the batch while still producing a coherent message. Together, these changes streamline the review-fix loop by reducing the manual overhead of tracking which suggestions were addressed, and bring Copilot's code review closer to the quality of a thoughtful human reviewer.
