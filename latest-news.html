Việc công bố bản thảo này được chú ý như một phát hiện tư liệu gốc quan trọng cho nghiên cứu văn học Nhật Bản.

06Claude Code fork() の使いどき — 並列エージェント設計の判断基準

📰 本文 + 和越対訳

Claude Codeでサブエージェントを並列実行する際のfork()とfresh agentの使い分けについて、実践的な判断基準をまとめた記事がZennで注目を集めている。fork()は「親のコンテキストが必要で、かつ子の生ログを親コンテキストに戻したくないとき」に最適だ。最大の利点はプロンプトキャッシュの共有で、5万トークンの重いセッションでも子エージェントは通常の約10分の1のコストで動作する。一方、独立した視点が必要な場合や別モデルを使いたい場合はfresh agentを選ぶべきだという。公式ドキュメントの "Don't peek" 原則（バックグラウンド実行中のforkのoutput_fileを途中で覗かない）についても詳しく解説されている。

Một bài viết trên Zenn đang thu hút chú ý về tiêu chí phân biệt khi nào dùng fork() và khi nào dùng fresh agent trong Claude Code. fork() tối ưu khi "cần context của agent cha, nhưng không muốn log thô của agent con quay trở lại context cha". Ưu điểm lớn nhất là chia sẻ prompt cache: ngay cả trong session nặng 50K token, agent con vẫn chạy với chi phí chỉ bằng 1/10. Ngược lại, khi cần góc nhìn độc lập hoặc muốn dùng model khác thì nên chọn fresh agent. Bài viết cũng giải thích chi tiết nguyên tắc "Don't peek" trong tài liệu chính thức (không được đọc file output_file của fork đang chạy ngầm).

11Agents Are Going Async: LangChain's Blueprint for Responsive, Multi-Task AI Agents

📰 Article (English)

LangChain engineers Sydney Runkle and Thushanth Bengre argue that the standard ReAct loop — where an agent blocks on each tool call and queues everything behind it — cannot be both responsive and productive simultaneously. The solution: split one orchestrator agent (stays in conversation with the user) from background worker subagents (run long-running tasks asynchronously and report back on completion). Claude Code already implements this pattern with its background subagent system; OpenAI's "dots" similarly hand work to background workers. LangChain is adding formal async subagent support to Deep Agents in Python and JavaScript with five orchestrator tools: start_async_task, check_async_task, update_async_task, cancel_async_task, and list_async_tasks. Each task supports an update_strategy field set to either "interrupt" (default: stop and restart the subagent when user sends a correction) or "enqueue" (hold the correction until current run finishes). The analogy drawn: a chief of staff who disappears until a project is done would be fired immediately. This orchestrator/subagent async split is framed as the defining architectural pattern for production agent systems in late 2026.
