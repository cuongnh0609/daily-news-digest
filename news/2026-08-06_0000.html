B-01Gitワークツリーで並行作業する——AIエージェントの手を止めない使い方

📰 本文 + 和越対訳

Gitのワークツリー（worktree）機能を活用することで、Claude Codeなどのエージェントが処理中であっても、開発者が別のブランチで並行して作業できることを紹介した記事がZennで注目を集めている。通常のgit checkoutでは一つのディレクトリしか操作できないが、git worktree addコマンドを使えば複数の作業ディレクトリを同時に持つことが可能になる。追加されたワークツリーは.gitオブジェクトデータベースを共有するため、ディスク容量の無駄がない。エージェントがタスクを処理している数分間の待ち時間を、別のworktreeで別のfeatureの実装に充てることで、実質的な並列作業が実現する。注意点としては、.envファイルやnode_modulesは自動的にコピーされないため、各worktreeで個別に設定が必要な点がある。また、同一ブランチを複数のworktreeに同時に展開することはできない。

Một bài viết trên Zenn thu hút sự chú ý khi giới thiệu cách dùng tính năng Git worktree để làm việc song song trên nhiều nhánh, ngay cả khi Claude Code hay agent khác đang xử lý tác vụ. Lệnh git checkout thông thường chỉ cho phép làm việc trên một thư mục, nhưng với git worktree add, bạn có thể duy trì nhiều thư mục làm việc độc lập cùng lúc, tất cả chia sẻ chung cơ sở dữ liệu đối tượng .git, không tốn thêm dung lượng đáng kể. Khoảng thời gian chờ agent xử lý (vài phút) có thể được tận dụng để triển khai tính năng khác trong worktree riêng, thực hiện công việc song song thực sự. Lưu ý: file .env và node_modules không được sao chép tự động sang worktree mới nên phải cài đặt riêng cho từng worktree.

C-02Building an Advanced Agentic Harness: DAG Planning, Multi-Tiered Memory, and Pressure-Aware Degradation

📰 Article (English)

A detailed engineering post on data4sci.com describes the architecture of a production-ready agentic harness built from composable primitives that mirror what systems like Claude Code and Cursor implement internally. The harness consists of nine components: a pluggable LLM backend with a shared interface for vendor independence and mock testing; typed Pydantic tools with automatic JSON schema generation; a DAG (Directed Acyclic Graph) planner that decomposes tasks into dependency graphs upfront rather than sequentially; a parallel async executor with semaphores for rate-limit protection; a multi-tiered memory system combining episodic and semantic retrieval; a verification hierarchy that runs cheap deterministic checks before expensive LLM judges; role-separated agents (Planner, Worker, Critic) with narrow contracts; multi-dimensional budgeting tracking tokens, tool calls, wall time, and cost simultaneously; and comprehensive structured tracing. The key insight is pressure-aware degradation: a single budget utilization scalar triggers automatic feature reduction — for example, skipping the LLM judge above 90% utilization — enabling graceful handling rather than hard failures. The author emphasizes that bad outputs propagate silently without verification hierarchies, making the verification component the most critical safety net in any production harness.

C-03Don't Be a Meat Proxy: Why Developers Must Add Intellectual Value Beyond Relaying AI Output

📰 Article (English)

Simon Willison's blog published a commentary on a piece by Niklas Gruhn coining the term "meat proxy" — a person who mechanically copies and pastes AI-generated output to others without adding any intellectual value. The term captures a growing failure mode in professional settings where AI tools are widely available: instead of using AI as a thinking accelerator, some people reduce themselves to a conduit between the AI and the final recipient. Gruhn's argument is that the actual professional value in an AI-assisted workflow comes from critical engagement: reading the output carefully, understanding it deeply, validating it against your domain knowledge, and then synthesizing it into your own words. Willison contextualizes this in the broader developer conversation: as AI coding assistants become ubiquitous, the engineers who thrive will be those who treat AI output as a first draft requiring their expert judgment — not a final product to be blindly shipped. The "meat proxy" anti-pattern is particularly dangerous in code review and architecture contexts where unverified AI suggestions can introduce subtle bugs or security vulnerabilities.
