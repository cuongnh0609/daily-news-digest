📰 本文 + 和越対訳

C-01Replit Rebuilds Sandbox Engine with microVMs — Agent-Native Infrastructure for Safe Code Execution

📰 Article (English)

Replit has completely rebuilt its sandbox engine from the ground up using microVM technology, announcing the milestone on its engineering blog. The new architecture replaces the previous container-based sandbox with Firecracker-powered microVMs, each booting in under 150 milliseconds with a full Linux kernel, isolated network stack, and ephemeral filesystem. The move was driven primarily by the demands of Replit's AI agent features, where autonomous code execution requires far stronger security guarantees than traditional containers can provide. MicroVMs offer hardware-level isolation, meaning a rogue agent or malicious code cannot escape the sandbox and affect the host or neighboring workloads. The team notes that the previous container approach had acceptable security for human-driven development, but agentic workflows that run untrusted tool-calling loops demand a different threat model entirely. Replit now runs millions of these microVMs daily, with each one provisioned on-demand per agent action and destroyed immediately after. The engineering blog post details how they handle cold-start latency at scale using snapshot-based boot, keeping median agent startup under 300ms. This architecture change has implications beyond Replit — it signals that the AI agent infrastructure layer is maturing and demanding dedicated primitives, not retrofits on top of existing container tooling.

Simon Willison đã xuất bản bài viết chi tiết về việc xây dựng một thế giới game persistent, multiplayer nơi mọi nhân vật NPC và sự kiện thế giới đều được điều khiển bởi các AI agent tự động dùng mô hình Fable-class (họ Claude 5), không có con người can thiệp trong quá trình vận hành liên tục. Dự án này chạy nhiều instance Fable-class đồng thời, mỗi instance đại diện cho một NPC khác nhau với bộ nhớ lâu dài, mục tiêu và tính cách riêng. Các agent dùng một world state chung lưu trong SQLite database — mỗi agent có thể đọc trạng thái, thực hiện hành động (di chuyển, nói chuyện, chế tạo, giao thương) và ghi lại thay đổi. Một coordinator agent quản lý thứ tự lượt đi và giải quyết xung đột khi hai agent cùng thay đổi một entity. Điểm mới về kiến trúc là không có behavior tree cứng nhắc: toàn bộ việc ra quyết định được giao hoàn toàn cho LLM thông qua tool call, với ràng buộc duy nhất là một tài liệu "constitution" mô tả luật của thế giới game. Willison ghi nhận nhiều hành vi emergent: các agent tự hình thành liên minh, một agent chuyên tích trữ tài nguyên, và một NPC từ chối nhận nhiệm vụ do "tâm trạng" trong context liên tục tiêu cực từ các tương tác trước đó. Bài viết bao gồm sơ đồ kiến trúc đầy đủ, schema SQLite và tất cả định nghĩa tool — đủ để tái tạo lại. Tác giả kết luận rằng mô hình Fable-class hiện đủ mạnh để duy trì lý luận long-horizon nhất quán trong một mô hình thế giới có ràng buộc, có ý nghĩa trực tiếp đối với các hệ thống agentic tự động trong production.
Bài viết này là tài liệu tham khảo thực tiễn hiếm có về multi-agent coordination với persistent state — nếu bạn đang thiết kế agent workflow cho production, schema SQLite và cơ chế conflict resolution của coordinator agent ở đây đáng đọc kỹ.

behavior tree /bɪˈheɪvjər triː/ Cấu trúc dữ liệu dạng cây dùng trong game AI để mô tả logic quyết định của NPC. Thường cứng nhắc, khác với LLM-driven decision making.

coordinator agent /koʊˈɔːrdɪneɪtər/ Agent đặc biệt trong kiến trúc multi-agent, chịu trách nhiệm điều phối, phân công và giải quyết xung đột giữa các agent khác.
