C1LangChain Deep Agents: Organizing Context in a Multi-Agent Harness

📰 Article (English)

LangChain's Deep Agents framework introduces a principled approach to context management when supervisor agents delegate tasks to subagents. The core insight is that not all subagents should receive the same context: a verifier agent checking output quality benefits from starting fresh with no prior anchoring bias, while a worker agent continuing mid-investigation benefits from inheriting the supervisor's full history. The framework exposes two explicit context modes. In isolated mode (the default), subagents receive only a task description — clean-room evaluation without contamination from the supervisor's reasoning chain. In forked mode, subagents inherit the supervisor's entire conversation history, formatted with a clarifying preamble that defines the agent's specialized role. The trailing tool call is stripped before forking to prevent replay confusion. Practical guidance: use forking for worker agents that pick up where context-gathering left off; use isolation for verifier agents, researcher agents with self-contained questions, and any agent where independent judgment is the point. Memory agents — which need to analyze full conversations to make durable decisions — require forking. Forked subagents automatically benefit from Anthropic's prompt caching, reducing latency and cost when the inherited context is long. The patterns are available in the deepagents package for Python and TypeScript.

Hướng dẫn thực tế: dùng forking cho worker agent tiếp tục từ chỗ đã thu thập context; dùng isolation cho verifier agent, researcher agent với câu hỏi độc lập, và bất kỳ agent nào cần phán đoán độc lập. Memory agent — cần phân tích toàn bộ hội thoại để đưa ra quyết định lâu dài — yêu cầu forking. Subagent fork tự động hưởng lợi từ prompt caching của Anthropic, giảm latency và chi phí khi context kế thừa dài.
Nếu bạn đang build multi-agent system, đây là blueprint cụ thể để quyết định khi nào subagent nên "thấy" lịch sử hội thoại — điều này ảnh hưởng trực tiếp đến độ chính xác và chi phí token của toàn hệ thống.

C2LangChain Connections: Per-Caller OAuth Identity for Production AI Agents

📰 Article (English)

LangChain's Managed Deep Agents v0.7.0 ships a feature called Connections that fundamentally changes how AI agents handle credentials in production. Rather than hardcoding secrets in .env files or embedding them in application code, Connections stores credentials in LangSmith workspaces — enabling rotation and revocation without redeployment. The design operates on two axes. First, agent-owned secrets are shared across all callers: a Tavily search API key the agent uses the same way for every user. Second, user-owned OAuth tokens resolve per-caller at runtime, giving each user their own identity for services like GitHub. This per-caller resolution means audit trails show which user triggered a specific agent action — critical for enterprise compliance. For developers, the impact is significant: no more callback routes, no token refresh logic, no session storage for third-party services. A single interrupt lists every OAuth connection the caller has not yet granted. The catalog ships with 22+ pre-configured services. MCP server integration is built in — when an agent connects to an MCP server requiring OAuth, Connections handles the flow transparently. This makes it practical to build agents that act as specific users across multiple third-party systems without writing authentication plumbing.

C3Anthropic Launches Enterprise Frontier Safeguards — Zero Data Retention Meets Automated Misuse Detection

📰 Article (English)

Anthropic announced Enterprise Frontier Safeguards (EFS), a three-part privacy and security framework developed in collaboration with over 100 enterprise customers across financial services, healthcare, manufacturing, telecom, legal, and retail sectors. The framework rolls out in phases beginning fall 2026. The three controls are: Customer-Controlled Data Storage — all data resides in the customer's own cloud infrastructure (AWS, Google Cloud, or Azure), never on Anthropic servers; Customer-Managed Encryption — organizations control their own encryption keys and access policies; and Automated Monitoring Without Human Review — Anthropic's systems analyze a rolling window of traffic for signals of serious misuse across multiple sessions and accounts, sending findings directly to the customer with no Anthropic employee ever reading the content. The automated cross-session monitoring is technically notable: it can detect patterns like credential theft attempts or coordinated cyberattack preparation that would be invisible within any single session. The findings go to the customer, not to Anthropic — a significant shift for organizations that needed zero data retention but also wanted misuse detection coverage. All three controls are opt-in. Eligible customers receive zero data retention on Fable 5 and Fable 5.1 during the rollout period. No changes to model behavior, API pricing, rate limits, or compatibility across Claude Code, Claude Enterprise, and cloud providers.
