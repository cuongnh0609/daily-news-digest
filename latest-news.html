B1Claude Codeの「キックオフ・テンプレート」を作った話 — INTENT.mdから始めるspec-drivenな開発

📰 本文 + 和越対訳

Claude Codeでの開発において、タスクを投げる前に「このセッションで何を達成したいか」を明示したINTENT.mdファイルを用意することで、エージェントの挙動が大幅に安定するという知見がZennで公開された。筆者はこのファイルを「キックオフ・テンプレート」と呼び、記述すべき項目として「ゴール（Goal）」「制約（Constraints）」「スコープ外（Out of scope）」「成功基準（Success criteria）」の4つを提案している。重要なのは、このファイルをClaude Codeが最初に読むファイルとして位置づけることで、途中でコンテキストが迷子になることを防ぐ点だ。実験では、INTENT.mdを用意した場合と用意しなかった場合では、タスク完了率と一発成功率に明確な差が出たという。これはいわゆる"spec-first"なアプローチであり、AIエージェントに対してもソフトウェアエンジニアリングの基本原則が有効であることを示す事例として、多くの開発者から関心を集めている。

Một bài viết trên Zenn đã chia sẻ phát hiện rằng việc chuẩn bị file INTENT.md — nêu rõ "muốn đạt được gì trong session này" trước khi giao task cho Claude Code — giúp hành vi của agent ổn định hơn đáng kể. Tác giả gọi file này là "kickoff template" và đề xuất 4 mục cần ghi: Goal (mục tiêu), Constraints (ràng buộc), Out of scope (ngoài phạm vi) và Success criteria (tiêu chí thành công). Điểm mấu chốt là đặt file này làm file đầu tiên Claude Code đọc, để ngăn context bị "lạc" ở giữa chừng. Thực nghiệm cho thấy có sự khác biệt rõ rệt về tỷ lệ hoàn thành task và tỷ lệ thành công ngay lần đầu giữa hai trường hợp có và không có INTENT.md. Đây là cách tiếp cận "spec-first" — bằng chứng cho thấy các nguyên tắc cơ bản của software engineering vẫn hiệu quả khi áp dụng cho AI agent.

C3Using LLM Self-Reported Confidence Scores Is a Bad Idea — Here's What to Build Instead

📰 Article (English)

A widely-shared engineering post argues that asking an LLM to rate its own confidence ("give this answer a score of 0–1") is fundamentally unreliable and should be replaced by observable-signal-based confidence computation. The argument: a trustworthy confidence score requires two properties — it must be grounded in evidence, and it must be calibrated against actual outcomes. LLM self-reports fail both. The model generates "0.85" as a plausible text continuation, not as a reading of an internal meter. Three effects illustrate this: asking the same question again changes the score, rephrasing it changes it, and preceding context sways it. The model was never trained to have stated confidence match real accuracy. The author proposes building an explicit confidence rule from observable signals: did retrieval find a relevant source? How many chunks matched? Do repeated independent runs agree? Does this question type have a strong track record? Combine these signals with a base rate from human-reviewed past outputs, log every prediction with its signals and eventual correctness, and recalibrate regularly per bucket. The practical example is a customer-support agent routing low-confidence answers to a human reviewer. The punchline is that the rule is only as good as the feedback loop — outcome tracking is non-negotiable.
