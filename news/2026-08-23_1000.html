11Why Your Local LLM Feels Dumber Than It Is: KV Cache Quantization and Inference Pipeline Divergence

📰 Article (English)

Local LLMs often feel significantly less capable than their reference implementations — and the culprit is rarely the model itself. A detailed investigation on the Level1Techs forum reveals that the performance gap stems from four implementation-specific factors. First, KV cache quantization: reducing key-value cache precision from BF16 to int4 caused complete tool-call failures in network automation tasks where BF16 succeeded — a reproducible, catastrophic accuracy drop. Second, weight quantization methodology: NVIDIA's NVFP4 quantization achieved ~50% token disagreement at 88k context length versus INT8 W8A16, which maintained superior fidelity. Third, attention backend selection: switching only the CUDA attention kernel (FlashAttention2 vs. FlashInference vs. Triton) caused measurable token prediction divergence, sometimes producing entirely wrong tool calls targeting incorrect network interfaces. Fourth, sampler settings drift: many local deployments ignore model-card-specified temperature and top-p values. The core insight is that "perceived model dumbness often reflects implementation choices rather than actual capability loss." Solutions include comprehensive benchmarking with realistic long-context workloads, verifying quantization methodology and calibration datasets, and strictly applying the sampler settings specified in the model card.
