B-01Claude Codeのhooksでrmコマンドをブロックしてわかった落とし穴——文字列マッチングの限界と対策

📰 本文 + 和越対訳

Claude CodeのPreToolUseフック機能を使ってBashツールの実行前に任意のスクリプトを挟み、rm -rfなどの危険なコマンドをブロックする試みが注目を集めている。フックはスクリプトの終了コードが2の場合にコマンドをブロックし、エラーメッセージをClaude本体に返す仕組みだ。実験ではrm -rf buildのブロックには成功したものの、rm -fr build（フラグの順序が逆）やfind -delete、xargs rm、Pythonのshutil.rmtreeなどは素通りすることが判明した。さらに、フック自体の依存ツール（jq）が存在しない場合や、"onFailure": "block"が設定されていない場合は全コマンドが通過してしまう問題もある。筆者は「hooksは文字列マッチングの安全網に過ぎず、サンドボックスにはなり得ない」と結論づけ、危険な操作はhooksではなくpermissions設定で制御することを推奨している。

Một thử nghiệm đang thu hút sự chú ý về việc sử dụng tính năng PreToolUse hook của Claude Code để chặn các lệnh nguy hiểm như rm -rf trước khi thực thi Bash tool. Hook hoạt động bằng cách block lệnh khi script trả về exit code 2 và gửi thông báo lỗi về cho Claude. Thử nghiệm cho thấy trong khi rm -rf build bị chặn thành công, các biến thể như rm -fr build (đảo thứ tự flag), find -delete, xargs rm, hay shutil.rmtree của Python lại không bị phát hiện. Tác giả kết luận rằng hooks chỉ là lưới an toàn dựa trên string matching, không thể thay thế sandbox, và khuyến nghị dùng cài đặt permissions để kiểm soát các thao tác nguy hiểm.

Benjamin Congdon argues that AI agents will fundamentally transform software operations monitoring. Traditional static alerts force a tradeoff between precision and noise: broad rules catch everything but page on false positives, while narrow rules miss emerging issues. Congdon proposes agents as a solution — they can write custom monitoring queries for each deployment event, scan logs extensively, and reason over code context to distinguish real incidents from noise. His prototype consists of three components: a planning agent that reads service code and generates monitoring specifications, a deterministic harness that executes those specs as structured checks, and an investigation agent that handles triggered monitors and escalates to humans. A key insight is that pure agent loops were inefficient and expensive, while a spec-based harness produced cleaner signals at much lower token cost. He identifies change-point monitoring — watching closely during and after deploys — as the highest-value initial use case, since most production outages originate from changes. Congdon estimates that monitoring a large service fleet with agents could cost around $100 per day and predicts this pattern will become standard practice. Early adopters who build agentic monitoring infrastructure now will gain significant operational advantages.
