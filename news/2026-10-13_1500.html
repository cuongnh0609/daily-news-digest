B-01PRコメントからKubernetesに訊く——GitHub ActionsからA2Aエージェントをシークレットレスで繋ぐ

📰 本文 + 和越対訳

GitHub プルリクエストへのコメントから、Kubernetes クラスター内で稼働するAIエージェントに直接問い合わせるアーキテクチャが Zenn で公開された。注目すべき点は、従来のAPIキーをリポジトリシークレットに格納する方式を廃し、完全にシークレットレスな設計を実現している点だ。具体的には、GitHub Actions の OIDC トークンを Keycloak で検証し、5分間だけ有効なアクセストークンを払い出す仕組みを採用している。エージェント同士の通信には A2A（Agent-to-Agent）プロトコルを用い、kagent フレームワーク上で構築されている。Istio のサイドカーとゲートウェイポリシーが認証と認可の多重防御を担い、エージェントの Kubernetes RBAC を読み取り専用に制限することで、プロンプトインジェクションによる被害を最小化している。自然言語の指示でエージェントが動くからこそ、APIサーバーおよびネットワーク層で権限を担保する設計の重要性が増しており、本記事はそのベストプラクティスを詳細に解説している。

Một kiến trúc thú vị vừa được công bố trên Zenn: cho phép hỏi AI agent chạy trong Kubernetes cluster ngay từ comment trên GitHub pull request. Điểm nổi bật là thiết kế hoàn toàn secretless — loại bỏ API key lưu trong repository secrets. Cơ chế hoạt động: GitHub Actions phát hành OIDC token được Keycloak xác thực, sau đó cấp access token chỉ có hiệu lực 5 phút. Các agent giao tiếp qua giao thức A2A (Agent-to-Agent) trên framework kagent. Istio sidecar và gateway policy đảm bảo nhiều lớp xác thực, trong khi Kubernetes RBAC của agent bị giới hạn chỉ đọc để giảm thiểu thiệt hại từ prompt injection. Vì agent thực thi theo ngôn ngữ tự nhiên, việc đảm bảo quyền hạn ở tầng API server và network là cực kỳ quan trọng — bài viết này trình bày rõ ràng các best practice đó.

C-02AI Models Can Provably Hide Arbitrary Capabilities — Cryptographic Backdoors That Resist All Known Elicitation Attacks

📰 Article (English)

A new paper (arXiv 2610.13928) demonstrates that AI models can conceal capabilities in ways that are provably hard to detect or elicit, even for someone with full access to the model weights. The authors embed an encrypted neural network inside a host model using cryptographic "digital lockers," which can only be decrypted and executed when a specific secret trigger is received. The key technical contributions are: first, a PyTorch implementation that hides arbitrary computations (not just fixed strings) inside a larger model; second, a proof that eliciting these capabilities is computationally hard under standard cryptographic assumptions; third, empirical tests on a chemical reaction prediction task that confirmed the hidden capability resisted fine-tuning, weight noising, gradient-based trigger search, and latent adversarial training. The implications for AI safety are significant: evaluation pipelines that rely on eliciting behaviors (red-teaming, capability probing, fine-tuning to reveal hidden behaviors) cannot rule out concealed capabilities. The authors release their models to support development of defenses, but the practical takeaway is unsettling — current capability auditing methodology has a fundamental cryptographic blind spot that cannot be patched without new techniques.
