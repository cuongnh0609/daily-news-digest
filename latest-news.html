B1Deno開発元がCloudflareに合流——Deno自体は終了へ、workerdとDurable Objectsのオープンソース化に注力

📰 本文 + 和越対訳

JavaScriptランタイム「Deno」の開発元であるDeno LandがCloudflareに合流することが発表された。今後1年間はDenoのバグ修正とセキュリティ更新が月次で提供されるが、その後はDenoの開発自体が終了する予定だ。商用サービス「Deno Deploy」も6か月後に終了し、利用者向けにCloudflare Workersへの移行支援が提供される。一方で、パッケージレジストリ「JSR」はCloudflareへ移管されて継続される見通しだ。Denoの作者であるライアン・ダール氏らは、Cloudflare Workersのオープンソースランタイムであるworkerdのセルフホスティングへの正式対応を主導する。また、ダール氏が開発した分散オブジェクト「celld」（Durable Objects互換の実装）をworkerdに統合し、クラウドベンダーへのロックインなしに分散アプリを構築・運用できる環境の実現を目指す。

Công ty phát triển JavaScript runtime "Deno" là Deno Land đã chính thức gia nhập Cloudflare. Trong vòng 1 năm tới sẽ tiếp tục có các bản cập nhật bảo mật hàng tháng, sau đó Deno sẽ kết thúc phát triển. Dịch vụ thương mại Deno Deploy cũng sẽ ngừng hoạt động sau 6 tháng, cung cấp hỗ trợ migrate sang Cloudflare Workers. Package registry JSR sẽ được chuyển sang Cloudflare và tiếp tục duy trì. Ryan Dahl và nhóm của ông sẽ dẫn đầu việc hỗ trợ self-hosting chính thức cho workerd (open source runtime của Cloudflare Workers). Họ cũng sẽ tích hợp celld — một implementation tương thích với Durable Objects — vào workerd, hướng tới môi trường xây dựng và vận hành ứng dụng phân tán không bị lock-in vào cloud vendor.

B2Gartner予測：2028年までにFDE（前線展開エンジニアリング）依存の企業の70%がエージェントAIを放棄

📰 本文 + 和越対訳

調査会社Gartnerは2026年9月、エージェント型AIの導入において「FDE（Forward Deployed Engineering）」に依存し続ける企業の70%が2028年までにそのシステムを放棄するという予測を発表した。FDEとは顧客環境に入り込んでAI実装を支援するベンダー提供のサービスモデルだが、Gartnerは「本物のFDE」と「コンサルティングの名称換え（FDEウォッシング）」を明確に区別する必要があると警鐘を鳴らす。本物のFDEが満たすべき3条件として、成果への責任・事業成果連動の報酬・顧客コードベースへの深い統合が挙げられている。また、企業が自立するための3段階——どこに使うかを慎重に選ぶ→社内人材と知識を移転する→出口条件を事前に決める——を踏まずにFDEに頼り続けると、結果としてコストが膨らみ本格運用に乗せられなくなるとGartnerは分析している。

C3Astral Integrates uv and ty: Unified Python Toolchain for Type-Checking, Dependencies, and Environments

📰 Article (English)

Astral, the company behind the Rust-based Python toolchain, announced an experimental integration between uv (Python package manager) and ty (type checker and language server). The integration allows each tool to leverage the other's strengths: uv knows the project's environment and dependencies, while ty understands the code. The first major feature is enhanced support for PEP 723 inline script metadata. ty now reads each script's declared dependencies, has uv automatically build an isolated environment for it, and type-checks the script against its specific requirements — even when they differ from the main project. In VS Code, this is enabled by setting ty.experimental.useUv to "on". The second feature is a new uv check command, which provides a unified diagnostic interface: it prepares the project environment, installs all dependencies, and runs type checking in a single step, using the ty version pinned in the lockfile so developers and CI get identical results. Support for Ruff is planned. The integration requires uv 0.12.3+ and ty 0.0.76+. Astral plans future cross-tool checks such as detecting unused dependencies by combining uv's dependency graph with ty's code analysis.
