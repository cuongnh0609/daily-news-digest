06Claude Code の fork() の使いどき — 並列エージェント設計の判断基準

📰 本文 + 和越対訳

Claude Code でサブエージェントを並列実行する際に、fork() と fresh agent のどちらを使うべきかという判断基準をまとめた記事がZennに公開され注目を集めている。fork() の最大の利点はキャッシュ共有にある。親セッションのコンテキストをそのまま引き継ぐため、5万トークン規模の重いセッションでも子エージェントは通常の約10分の1のコストで動作する。比較すると、親コンテキストが必要な場合は fork()、独立した視点や別モデルが必要な場合は fresh agent、軽量な単発タスクには fresh agent が適している。また、実装パターンとして誇張チェック・ターゲット適合・内部リンクの3つの確認を同時にforkで並列起動する設計例が示されている。さらに、公式ドキュメントが定める "Don't peek" 原則——バックグラウンド実行中の fork の出力ファイルを途中で読まない——についても解説されている。

Một bài viết trên Zenn tổng hợp tiêu chí để quyết định dùng fork() hay fresh agent khi chạy parallel subagents trong Claude Code đang thu hút nhiều chú ý. Lợi thế lớn nhất của fork() là chia sẻ cache: vì kế thừa toàn bộ context của session cha, nên dù session có tới 50.000 token, agent con vẫn chạy với chi phí chỉ bằng 1/10. So sánh lại: cần context của cha thì dùng fork(), cần góc nhìn độc lập hoặc model khác thì dùng fresh agent, task đơn giản một lần dùng fresh agent. Bài viết cũng trình bày ví dụ thiết kế song song 3 fork đồng thời cho kiểm tra phóng đại, kiểm tra phù hợp target và kiểm tra liên kết nội bộ. Ngoài ra còn giải thích nguyên tắc "Don't peek" trong tài liệu chính thức — không đọc file output của fork đang chạy ngầm.

07CLAUDE.md をユーザー共通とリポジトリごとに分けて運用する話 — 何をどちらに書くか

📰 本文 + 和越対訳

複数の社内ツールリポジトリを1人で管理する際の CLAUDE.md 分割運用法を紹介したZennの記事が話題となっている。著者の判断軸は「別のリポジトリでこの1行を読んだとき、Claude Codeが困るか」という一点に集約される。ユーザー共通の ~/.claude/CLAUDE.md にはソース管理方針・返答言語・記録の振り分けルールなど全プロジェクト横断の決まりを記述する。一方、リポジトリ固有の CLAUDE.md にはビルドコマンド・ディレクトリ構成・本番反映手順・業務ルールといった、そのツール専用の情報を書く。読み込み確認は /memory コマンドよりも /context コマンドの「Memory Files」セクションを確認するほうが確実。この分け方により、複数リポジトリに同じ設定をコピーする手間と陳腐化を防ぐことができる。

Một bài viết trên Zenn hướng dẫn cách tách biệt CLAUDE.md thành phần chung cho người dùng và phần riêng cho từng repository khi quản lý một mình nhiều repo công cụ nội bộ đang được chú ý. Tiêu chí phán đoán của tác giả chỉ gói gọn ở một điểm: "Nếu Claude Code đọc dòng này ở một repo khác, nó có bị rối không?" File chung ~/.claude/CLAUDE.md ghi các quy tắc xuyên suốt mọi dự án như chính sách quản lý source code, ngôn ngữ trả lời. File riêng của từng repo thì ghi thông tin chuyên dụng như lệnh build, cấu trúc thư mục, quy trình deploy lên production. Để kiểm tra file nào được nạp vào, dùng lệnh /context xem mục "Memory Files" đáng tin hơn /memory. Cách tách này giúp tránh phải copy cùng cấu hình sang nhiều repo và tránh nội dung bị lỗi thời.

Anthropic announced it is donating Agent Skills — the open standard for giving AI agents specialized knowledge and reusable workflows — to the Agentic AI Foundation (AAIF) under the Linux Foundation umbrella. A "skill" is a folder built around a SKILL.md file with YAML frontmatter (name + description required), optionally bundled with scripts or reference materials. When Claude Code or any compatible agent starts, it pre-loads skill metadata from all installed skills, then loads full skill content only when that skill becomes relevant — a progressive disclosure model that keeps context window usage minimal while giving the agent access to unbounded knowledge. The Foundation — co-founded by Anthropic, Block, and OpenAI — already hosts the Model Context Protocol (MCP). Lead Maintainers will be David Soria Parra and Mahesh Murag. The planned roadmap includes versioned releases, a formal proposal process for new skill primitives, and security guidance for skills with executable scripts. By moving to a neutral foundation, Agent Skills becomes vendor-neutral portable procedural knowledge, reducing single-vendor lock-in risk.

11Agents Are Going Async — LangChain Introduces Orchestrator/Subagent Split for Production Systems

📰 Article (English)

LangChain engineers Sydney Runkle and Thushanth Bengre argue that the standard ReAct loop — where an agent blocks on each tool call, forcing every other task to queue behind it — cannot be both responsive and productive simultaneously. The emerging solution: split one orchestrator agent (which stays in conversation with the user) from background worker subagents (which run long-running tasks asynchronously and report back on completion). Claude Code already implements this pattern with its background subagent system; OpenAI's "background workers" and DeepSeek Harness are cited as parallel developments. LangChain is adding formal async subagent support to Deep Agents in Python and JavaScript with five orchestrator tools: start_async_task, check_async_task, update_async_task, cancel_async_task, and list_async_tasks. Each task supports an update_strategy field set to either "interrupt" (default: stop and restart the subagent when the user sends a correction) or "enqueue" (hold the correction until the current run finishes). The analogy is vivid: a chief of staff who disappears until a project is done would be fired immediately — a good one stays reachable and provides updates while keeping work moving. The article frames this orchestrator/subagent async split as the defining architectural pattern for production agent systems in late 2026.

🇻🇳 Bản dịch + 📖 Giải thích thuật ngữ
Hai kỹ sư của LangChain lập luận rằng vòng lặp ReAct tiêu chuẩn — nơi agent chặn tại mỗi tool call, buộc mọi tác vụ khác phải xếp hàng — không thể vừa phản hồi nhanh vừa làm nhiều việc song song cùng lúc. Giải pháp đang nổi lên: tách một orchestrator agent (tiếp tục ở lại với người dùng) khỏi các background worker subagent (chạy tác vụ dài hạn bất đồng bộ và báo cáo khi hoàn thành). Claude Code đã triển khai pattern này với hệ thống background subagent; "background workers" của OpenAI và DeepSeek Harness được đề cập như các phát triển song song. LangChain đang bổ sung hỗ trợ async subagent chính thức vào Deep Agents với 5 công cụ orchestrator: start_async_task, check_async_task, update_async_task, cancel_async_task và list_async_tasks. Mỗi task hỗ trợ trường update_strategy với 2 giá trị: "interrupt" (mặc định — dừng và khởi động lại subagent khi người dùng gửi chỉnh sửa) hoặc "enqueue" (giữ chỉnh sửa đến khi lần chạy hiện tại xong). Ẩn dụ rất sống động: một chánh văn phòng biến mất cho đến khi dự án xong sẽ bị sa thải ngay — người giỏi phải vừa báo cáo tiến độ vừa tiếp tục làm việc. Bài viết định hình pattern tách orchestrator/subagent async này là kiến trúc chuẩn của production agent trong cuối năm 2026.
Nếu bạn đang build agent với LangGraph hoặc bất kỳ framework nào, hãy xem xét refactor sang kiến trúc orchestrator + background subagent — đây là hướng toàn ngành đang đi, và Claude Code đã triển khai sẵn.
