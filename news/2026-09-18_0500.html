B-01なぜ「Claude Code」で想定外のコストになるのか——トークン浪費を防ぐ4つの実践的ポイント

📰 本文 + 和越対訳

Claude Codeを実務で使い始めたエンジニアの間で、「思ったよりもトークン消費が多くてコストが膨らんだ」という報告が増えている。ITメディアのatmarkitが整理した分析によると、主な原因は三つある。第一に、プロンプトキャッシングによって前回セッションのコンテキストが引き継がれるため、新規タスク開始時にも余分なトークンが消費される。第二に、ファイル読み込み時に関連ファイルの検索結果がコンテキストに自動で含まれ、意図しないトークン増加を招く。第三に、コマンド実行結果がセッション中に蓄積され続けることで、長いセッションほど累積消費量が増える。対策としては、作業開始前に/clearでコンテキストをリセットする、/compactでキャッシュ効率を上げる、ファイル参照時はパスを明示してサーチを省く、という具体的な手法が有効だ。また、新規タスクを始める前にモデルとエフォートレベルを適切に設定することでも、無駄なトークン消費を大幅に削減できる。

Ngày càng có nhiều kỹ sư sử dụng Claude Code trong công việc thực tế báo cáo rằng "chi phí token cao hơn dự kiến." GitHub has promoted Workflow Execution Protections to general availability for GitHub Actions, addressing one of the most dangerous attack vectors in open-source CI/CD: the "Pwn Request" exploit. This class of attack occurs when untrusted code from a forked repository can trigger a pull_request_target workflow that has access to repository secrets, allowing attackers to exfiltrate credentials and poison the build pipeline. The GA release includes several new capabilities: workflow file targeting lets teams restrict which specific workflow files can be triggered; an insights dashboard provides policy auditing across an organization's repositories; and a REST API enables programmatic management of protection rules. An "evaluate mode" allows organizations to test protection rules before enforcing them, reducing friction for gradual adoption. Enterprise teams managing open-source projects or accepting external contributions should prioritize this feature to prevent supply chain compromises via CI/CD pipelines.
