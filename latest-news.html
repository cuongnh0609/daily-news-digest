B1NVIDIAの「長文コンテキスト不要」論文 — エージェンティックな圧縮・選択的読み込みでLLMコスト削減

📰 本文 + 和越対訳

NVIDIAの研究チームが発表したarXiv論文（2611.05306）が、AI推論コストを大幅に削減できる可能性を示すとして注目を集めている。従来のAIエージェントは長い会話履歴をすべてコンテキストウィンドウに詰め込む手法が主流だったが、この論文では「圧縮してから選択的に読み込む」というアーキテクチャを提案している。具体的には、過去の履歴を都度コンパクトに「圧縮」し、必要な箇所のみを「選択的に読み込む」ことで、実質的に長文コンテキストを必要としない状態でSWE-benchやLOONGなどの各種ベンチマークで同等以上の成果を出している。ただし、エージェンティック検索を多用する手法のため回答までの時間が長くなる傾向があり、速度とコストのトレードオフが課題として残る。LLMの利用コストに悩むエンジニアには実践的な示唆をもたらす研究といえる。

Đội nghiên cứu NVIDIA công bố bài báo arXiv (2611.05306) đề xuất kiến trúc agent không cần long context: thay vì nhồi toàn bộ lịch sử hội thoại vào context window, hệ thống "nén" trạng thái liên tục và chỉ "đọc chọn lọc" phần cần thiết. Phương pháp này đạt kết quả tương đương hoặc tốt hơn trên các benchmark SWE-bench và LOONG, trong khi giảm đáng kể chi phí inference của LLM. Hạn chế là thời gian phản hồi dài hơn do sử dụng nhiều agentic search. Đây là nghiên cứu thực tế hữu ích cho engineer đang tìm cách tối ưu chi phí LLM trong production.

C2LangChain Introduces Eval-Driven Development (EDD): Write Evals First, Build Agents Toward Them

📰 Article (English)

LangChain published a detailed methodology post on Eval-Driven Development (EDD) — a structured approach to building AI agents that borrows its philosophy from Test-Driven Development. The core insight is that agents built by iterating "try it and see" work early but degrade unpredictably as scope expands, because there's no stable definition of "working." EDD fixes this by defining desired agent behaviors upfront and writing evaluations (evals) before building the system that should pass them. Each eval targets one behavior in isolation so changes have clear, measurable effects. The workflow: define the behavior, collect or generate test cases, pick an evaluation metric (LLM-as-judge, human label, deterministic check), build toward passing the eval, then repeat for the next behavior. LangSmith integrates the eval harness so teams can track regression across experiments. LangChain argues this discipline becomes critical once you move beyond single-agent demos to production multi-agent systems where failures compound non-linearly. The post includes worked examples of how behavioral specs translate directly into eval cases.
