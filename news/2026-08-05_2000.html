A5Googleパスワードマネジャーに3種の脆弱性——パスキー保護アカウントでも乗っ取りが可能

📰 本文 + 和越対訳

セキュリティ企業パロアルトネットワークスの研究チーム「Unit 42」は、Googleパスワードマネジャーに関する3種類の脆弱性を公表した。 攻撃の前提条件として標的PCへのマルウェア感染が必要となるが、いずれもパスキー認証で守られたアカウントを乗っ取れる手法だ。 「Pass-ta-key」はTPMからIDキーを取得してサービス側の不十分な本人確認を突く。「Silver Pass-ta-key」は既存キーを強制的に再登録させて偽キーを正規キーとして保存する。「Golden Pass-ta-key」は同期済みパスキーの復号に使われるマスターキーを、再登録時のメモリから平文で盗む。 研究チームはサービス事業者に対し、デバイス再登録の不審な繰り返しを検知すること、および本人確認情報の確実な検証を求めている。 eBayでは「Pass-ta-key」による攻撃の成功事例も確認されており、実被害が出る前に対策が急がれている。

Nhóm nghiên cứu bảo mật Unit 42 của Palo Alto Networks đã công bố 3 loại lỗ hổng trong Google Password Manager. Mặc dù điều kiện tiên quyết là máy tính nạn nhân phải bị nhiễm malware, cả 3 đều có thể chiếm quyền tài khoản được bảo vệ bằng passkey. "Pass-ta-key" khai thác việc xác thực danh tính không đủ chặt ở phía dịch vụ bằng cách lấy ID key từ TPM. "Silver Pass-ta-key" cưỡng bức đăng ký lại key hiện tại rồi lưu key giả như key hợp lệ. "Golden Pass-ta-key" đánh cắp master key dùng để giải mã passkey đã đồng bộ từ bộ nhớ dưới dạng plaintext trong quá trình đăng ký lại. Nhóm nghiên cứu khuyến nghị các nhà cung cấp dịch vụ cần phát hiện các lần đăng ký lại thiết bị bất thường và xác thực danh tính chặt chẽ hơn.

B1Claude Code の「無駄」を可視化する Rust 製 CLI ツール cclens が登場

📰 本文 + 和越対訳

Rust で実装された CLI ツール cclens（Claude Code Lens の略）が公開された。 Claude Code を日常的に使う開発者向けに、設定ファイルやセッションログを解析し、コンテキスト消費の「無駄」を可視化・最適化することを目的としたツールだ。 主要コマンドは doctor（全体的な健康診断をワンスクリーンで表示）、overhead（毎セッション必ず消費されるトークン量を設定ファイル由来・基盤由来に分解）、optimize（検出した無駄をAIに渡して最適化提案を取得）の3つ。 特徴は「計測のための追加コストをゼロに近づける」設計で、追加のプロキシや wrapper を立てることなく、既存ログを事後分析する形を採る。 ローカル完結型のため、プロンプトや会話内容が外部に送信されることはなく、「推測するな、計測せよ」という原則に基づいている。 プラグイン形式でセッション内から /cclens doctor のように呼び出すことも可能だ。

Công cụ CLI cclens (viết tắt của Claude Code Lens) được implement bằng Rust đã được phát hành. Đây là công cụ dành cho developer sử dụng Claude Code thường xuyên, phân tích file cấu hình và session log để trực quan hóa và tối ưu hóa "sự lãng phí" trong việc tiêu thụ context. Các lệnh chính gồm doctor (kiểm tra tổng thể trên một màn hình), overhead (phân tích lượng token tiêu thụ bắt buộc mỗi phiên theo nguồn gốc từ file cấu hình hay từ nền tảng), và optimize (chuyển vấn đề phát hiện được cho AI để nhận đề xuất tối ưu). Thiết kế hoàn toàn chạy local, không gửi prompt hay nội dung hội thoại ra ngoài. Có thể gọi dưới dạng plugin trực tiếp trong session bằng lệnh như /cclens doctor.

C1Stateless MCP 2.0 Eliminates Session Management — Single-Request Protocol Reignites Interest

📰 Article (English)

The Model Context Protocol (MCP) received its most significant update since launch in July 2026, with the introduction of a stateless design that removes the session management overhead that had frustrated developers. Previously, calling an MCP tool required two HTTP round-trips: an initialization request to obtain a session ID, followed by the actual tool call. Stateless MCP collapses this into a single request by moving client metadata into request headers, eliminating server-side session state entirely. Simon Willison, who documented the update extensively, argues that this architectural shift makes MCP significantly safer as an agent integration pattern. Compared to giving AI systems shell access or open internet browsing, MCP tools provide a bounded, auditable surface — and with stateless connections, they become far easier to deploy as simple serverless functions or edge workers with no persistence layer. Smaller models can also use MCP tools reliably because the protocol interaction is now simpler. Willison shipped three projects to demonstrate the new protocol: mcp-explorer (a CLI for inspecting any MCP server), datasette-mcp (SQL query access over MCP), and llm-mcp-client (integrating MCP into his LLM CLI tool). Each required minimal code, signaling that the developer experience has genuinely improved with this release.

🔴 HIGH IMPACT Breaking design change — existing MCP servers using session-based flow should plan migration to stateless endpoints for scalability and simplicity.

C3Kioxia Launches XL1 CXL Flash Module — A New Memory Tier Between DRAM and SSD for AI Workloads

📰 Article (English)

Kioxia announced the XL1 Series memory expansion module on August 3, 2026, targeting AI inference and hyperscale data center deployments that are running into DRAM capacity limits. The product combines the company's XL-FLASH low-latency NAND technology with a CXL (Compute Express Link) interface to create a new memory tier positioned between conventional DRAM and standard SSDs. The core use case is tiered memory: frequently accessed data stays in DRAM, while less-accessed but still hot data is offloaded to the XL1 module. Because XL-FLASH is purpose-built for low latency — far below what standard NAND SSDs achieve — the performance penalty of offloading to XL1 is much smaller than moving data to an SSD. The result is an effective increase in total addressable memory per node without the cost or physical constraints of adding more DRAM DIMMs. Kioxia will ship evaluation samples to industry partners within the month and will demonstrate the XL1 at FMS: The Future of Memory and Storage in Santa Clara. The timing aligns with growing demand from AI training and inference clusters where model weights and KV-cache are consuming increasingly large amounts of high-bandwidth memory. The XL1 positions Kioxia competitively in the CXL memory expansion space alongside Samsung's CMM-H and SK Hynix's AiMX offerings.
