B-01PostgreSQL + pgvector 一択——CerebrasがRAGで社内ナレッジ管理を再設計した3つの教訓

📰 本文 + 和越対訳

AIスタートアップのCerebrasが自社の社内ナレッジ管理システムをRAG（検索拡張生成）技術を用いて再構築した事例が注目を集めている。特徴的なのは、Pineconeなどの専用ベクトルデータベースを採用せず、すべてをPostgreSQLにpgvector拡張で統一したことだ。キーワード検索（GINインデックス）・ベクトル検索・IFDスコアリング・新しさによる重み付けを組み合わせ、相互ランク融合（Reciprocal Rank Fusion）で検索精度を高めている。また、Slackのチャット生データを直接インデックス化するのではなく、LLMで会話スレッド全体を構造化ドキュメントに変換してから格納するという前処理が鍵となっている。AIに直接回答させるのではなく、MCPを通じてきめ細かい検索プリミティブをツールとして公開する設計も示唆に富む。

Trường hợp tái thiết kế hệ thống quản lý kiến thức nội bộ của startup AI Cerebras sử dụng công nghệ RAG (Retrieval-Augmented Generation) đang thu hút sự chú ý. Điểm đặc biệt là họ không dùng cơ sở dữ liệu vector chuyên dụng như Pinecone mà thống nhất tất cả vào PostgreSQL với extension pgvector. Hệ thống kết hợp tìm kiếm keyword (chỉ mục GIN), tìm kiếm vector, IDF scoring và trọng số theo độ mới, tăng cường độ chính xác bằng Reciprocal Rank Fusion. Một điểm quan trọng khác là tiền xử lý dữ liệu Slack: thay vì index trực tiếp raw chat, toàn bộ thread hội thoại được chuyển đổi thành tài liệu có cấu trúc qua LLM trước khi lưu trữ. Kiến trúc công khai các search primitive qua MCP thay vì cho AI trả lời trực tiếp cũng rất đáng học hỏi.

B-02AIエージェント向けツールはMCPではなくCLIで作る——ファイル直渡し・文脈温存・エラー回復の3原則

📰 本文 + 和越対訳

AIエージェントとデータノートブックをつなぐCLIツール「cdm」の開発者が、MCP（Model Context Protocol）サーバーではなくコマンドラインツールとして設計した理由と、その3つの設計原則を公開した。第一の原則は「ファイルを引数として直接渡す」こと。MCPのようにリクエストボディを構築させると不要なトークンを消費するのに対し、CLIではファイルそのものを引数として扱えるため効率的だ。第二は「文脈の温存」——モデルの事前学習を活かし、JSONよりMarkdownを優先し、ドキュメントはオンデマンドで取得させる。第三は「エラー回復の設計」——バリデーションや自動修正機能を組み込み、制約的なプロンプトではなくツール設計そのものでエラーに対処する。このアプローチはMCP不要論ではなく、ツールの特性に応じた使い分けを提唱している。

Nhà phát triển công cụ CLI "cdm" kết nối AI agent với data notebook đã chia sẻ lý do chọn command-line tool thay vì MCP server, cùng ba nguyên tắc thiết kế. Nguyên tắc thứ nhất là "truyền file trực tiếp làm đối số" — so với MCP phải xây dựng request body tốn token, CLI có thể xử lý file trực tiếp hiệu quả hơn. A new open-source project called Swiftlet enables running frontier-scale large language models — specifically Qwen3-Next-80B and Qwen3.6-35B — on consumer Apple hardware with dramatically reduced RAM requirements. The key architectural innovation is targeting Mixture-of-Experts (MoE) models, which activate only approximately 3 billion parameters per token. Swiftlet keeps dense weights resident in memory while streaming routed expert weights on demand from disk using efficient pread calls and fixed-stride expert containers. Both models eliminate the growing KV cache problem at extended contexts by using gated DeltaNet linear attention with a fixed-size recurrent state. The project advances practical private, offline LLM inference on mainstream hardware.
